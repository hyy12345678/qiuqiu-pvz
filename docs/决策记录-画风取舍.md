# 决策记录：画风方向（放弃《旷野之息》风格）

> 日期：2026-11-23
> 决策人：项目作者
> 结论：**不追求《旷野之息》那类 3D 厚涂风格**，沿现有「柔和渐变 + 统一光照」的路线收敛。
>
> **已被取代（E28）**：本记录的前提是「2D 程序绘制」，在那个前提下结论成立。E28 改成 three.js 真 3D 渲染，
> 体积与光照由渲染器给出，第 4 节的尺寸瓶颈不再适用。见 [E28-3D画面重做](工程执行计划-E28-3D画面重做.md)。

## 1. 问题从哪来

E14–E16 三轮画面迭代之后，作者提出：「能做成塞尔达荒野之息的那种卡通风格吗？」

## 2. 为什么原版风格不可能

《旷野之息》的观感依赖三件事，这个项目一件都不具备：

| 依赖 | 本项目 |
|---|---|
| 3D 几何 + 实时光照 | 2D Canvas，全部程序绘制 |
| 手绘贴图（岩石/草地的笔触） | **零位图**，只有代码画出来的形状 |
| 泛光、景深、大气散射 | 单 Canvas 2D，只能粗糙近似 |

它那种"卡通"不是动漫赛璐璐，而是**吉卜力式厚涂**，本质是贴图与光照的密度，不是描边风格。

## 3. 做过的两个实验（均已回退）

### 3.1 后期调色

在 `render/scenes/index.js` 末尾加一层后处理：`soft-light` 竖向四段分级（上冷 / 中暖 / 下压暗）+
天际线空气透视 + `screen` 亮度回补。

**结果**：能跑、无报错，画面确实更暖更饱和，但**离目标差一个数量级**。
`soft-light` 在中间调上的作用本来就温和，加大透明度只会往"过曝/脏色"走。

### 3.2 赛璐璐上色（单株向日葵样张）

把向日葵改成硬边两色阶：花瓣整片中间调 + 左上硬高光块，花盘三个硬边色块，描边加粗。

**结果：比原版更难看。** 花瓣高光变成一个个"胶囊"，整体发闷，花盘丢掉体积感。

## 4. 失败原因：尺寸（本轮最重要的结论）

| 量 | 值 |
|---|---|
| 逻辑分辨率 | 1024 × 640 |
| 单个格子 | 80 × 96 px |
| 向日葵实际高度 | **约 50 px** |
| 单片花瓣 | **约 13 × 26 px** |

**赛璐璐靠"硬边色阶"起作用，而硬边需要像素去承载。** 13 像素宽的花瓣放不下两条色阶，
边界必然糊成噪点。这套画法是为大尺寸角色（立绘、3A 模型）设计的。

反过来也解释了为什么 E14–E16 的"柔和渐变"有效：**柔和过渡在低像素量下不会崩。**

## 5. 唯一能真正到那个档次的路

**手绘贴图 + base64 内嵌。**

关键认知：**「单文件零资源」禁的是外部资源，不是内嵌位图。**
把 PNG/WebP 以 data URI 塞进产物，它仍然是一个文件、完全离线、双击即玩。

| 项 | 现在 | 改成贴图 |
|---|---|---|
| 文件大小 | 179 KB | 约 1~3 MB |
| 离线 / 单文件 | ✅ / ✅ | ✅ / ✅ |
| 角色观感 | 程序绘制的矢量风 | 可做到任意画风 |
| 谁来做 | 写代码 | **需要画师**（Procreate / Aseprite） |

这条路**技术上可行但不是代码问题**，是美术资产生产问题。本轮不启动，
但管线改造（把 `drawPlantEntity` / `drawZombieEntity` 改成画内嵌精灵图、保留程序绘制作 fallback）
随时可以按需开工。

## 6. 因此确定的路线

1. 画风沿「柔和渐变 + 统一光照（左上）」收敛，不再尝试硬边/厚涂方向。
2. 后续画面工作只做**细节密度**（褶皱、叶脉、砖缝一类），不做风格迁移。
3. 若作者日后提供手绘素材，再启动内嵌精灵图管线。

## 7. 本轮的痕迹

两个实验均已回退：工作区无未提交改动，`parity` 与 `fingerprint` 均 PASS，`dist` 维持 179.4 KB。
本轮唯一产出是这份决策记录。
