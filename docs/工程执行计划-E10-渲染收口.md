# E10 执行计划（渲染层三处收口 + 一条不变量的记录）

> 日期：2026-11-20
> 上游依据：[docs/项目分析-2026-11-20.md](项目分析-2026-11-20.md) §5.2 中剩余的低severity 项、§8 风险清单第 6 条。
> 本轮性质：**缺陷收口**。画面必须逐像素不变。

## 1. 三处改动

### 1.1 `render/scenes/index.js`：`restore` 移进 `finally`

原实现：

```js
ctx.save();
... 分派场景，可能抛错 ...
ctx.restore();
```

绘制一旦抛错，`restore` 被跳过，**ctx 的 save 栈永久错位**。后果不是"这一帧没画好"，
而是之后每一帧都画在上一层变换上、暗角再压一层——故障会从"某个场景报错"扩散成"画面整体漂移"，
极难诊断。改为 `try { … } finally { ctx.restore() }`：异常仍然向上抛，但栈不会坏。

### 1.2 `render/scenes/play.js`：僵尸按行分桶一次

原实现每帧对 5 行各做一次 `world.zombies.filter(...).sort(...)`，即 5 次全表扫描 + 5 次数组分配 + 5 次排序。
改为先分桶、再每行排一次。**绘制顺序完全一致**（行内仍按 x 升序），只是少做了 4 次全表扫描。

### 1.3 `render/hud.js`：8 卡硬编码提成命名常量

`CARD_X0 + 8*(CARD_W+CARD_GAP)` 里的 `8` 是"卡槽按最宽关卡预留"的布局常量，
却被写成了裸数字。提成 `MAX_CARDS` 并注明：**不能改成读 `world.slots.length`**——
那样 6/7 卡关卡里铲子按钮会左右跳。

## 2. 一处不改，只把不变量写清楚

`core/actions.js` 的咖啡豆分支不校验阳光（`inspectUseCard` 注释里原写作"沿用旧规则"）。
分析报告标为"低 · 实际不可达"。本轮复核后确认**确实不可达**：

- 选卡入口 `pickSlot` 已要求 `world.sun >= def.cost`；
- 一次只能选中一张卡；
- 从选中到点格子之间，没有任何路径能让阳光减少。

因此**不加检查**——加一个永远不会触发的分支只会增加噪音。改为把不可达的**理由**写进注释，
并写明什么条件下这个前提会失效（同时选中多张卡、或选卡后仍可消费阳光），届时必须补校验。

## 3. 验收

### 3.1 parity 差异逐行核对

**移除 3 行 / 新增 9 行**，全部对应上述三处：

| 移除 | 新增 |
|---|---|
| `const sx = CARD_X0 + 8*(CARD_W+CARD_GAP) + 8, sy = BANK_Y+8;` | `const MAX_CARDS = 8;` + `const sx = CARD_X0 + MAX_CARDS*(…)` |
| `const zs = world.zombies.filter(...).sort(...);` | `const zombiesByRow = Array.from(...)` + 3 行分桶/排序 |
| `for(const z of zs) drawZombieEntity(t, z);` | `for(const z of zombiesByRow[r]) drawZombieEntity(t, z);` |
| — | `try {` / `} finally {` / `}` |

`actions.js` 的注释改动**不出现在 parity 里**（parity 剥注释），由 `fingerprint` 覆盖。

## 4. 遗留

- 分析报告 §5.2 的"悬停矩形判定重复 6 处 / 面板底纹重复 4 处"仍是重复代码，
  但它们分散在五个场景文件里，抽取会牵动各场景的布局参数，收益低于风险，**判断为不做**。
- "每帧新建渐变"（HUD 每张卡一个径向渐变）是性能项，实测满场 129 渐变/帧仍在安全区内，
  依据"性能优化必须先有测量证据"的项目原则，**没有测量到瓶颈就不做**。
