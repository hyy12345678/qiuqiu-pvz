# E14 执行计划（画面精细度：背景层 + 一个被护栏抓到的真 bug）

> 日期：2026-11-20
> 起因：用户反馈「画面不够精细」。这是本系列第一次**改画面**，此前 13 轮全是结构/护栏工作。
> 性质：**美术迭代**。按 E8 的结论，这类改动的代价是重盖绘制基线——本轮实测兑现了那次判断。

## 1. 先看，再改

没有凭想象提方案。用 Playwright 在 `deviceScaleFactor: 3` 下抓了整屏与 3 倍裁切，
逐处看细节。结论是**战斗画面 70% 是草坪，而草坪是一片平涂的棋盘绿**，所以整体发"平"。

四类具体问题（3x 裁切下才看得见）：

| 位置 | 问题 |
|---|---|
| 草坪 | 每格是纯色渐变，没有任何内部起伏；草丛是三个直上直下的短划，放大后像排版符号 |
| 房屋 | 整面墙是一片平色 + 横线，没有明暗、没有木纹、屋檐下没有投影 |
| 泥土带 | 几团软斑，没有石子、没有与两侧的边界阴影 |
| 窗户 | 平面蓝块，没有玻璃深度 |

**关键机会**：背景是整幅预渲染后缓存进离屏画布的，往里加多少细节都**零运行时开销**。

## 2. 改了什么（全部在 `paintBattleBG` 的缓存层内）

| 函数 | 改动 |
|---|---|
| `paintLawn` | 每格 16 道横向拉长的草丝光泽；竖向割草条纹；草丛改为每丛 3~5 片**扇形张开的草叶**（带弧度、三档色调）；新增左侧房屋软阴影、顶部栅栏窄阴影、四周径向压暗 |
| `paintHouse` | 木板缝下沿高光、竖向木纹短划、檐口投影、墙脚投影 |
| `paintDirtStrip` | 70 颗小石子（上亮下暗）、靠草坪与靠房屋两侧的边界阴影 |

调参过程记录：第一版草丝半径 7~27px、不透明度 0.15，**放大后像一层绿泡泡**；
改成扁平拉长（ry = rx·0.2~0.36）、不透明度 0.085，才读成草面反光。

## 3. 一个真 bug，以及抓到它的那条护栏

改完 `paintHouse` 时我用了随机流 `R()`，但那个函数的签名里**没有 `R`**（它原来不消耗随机数）。
于是 `paintBattleBG` 抛 `ReferenceError: R is not defined`。

后果不是"画错一点"，而是**整个游戏静默冻死**：
[src/game.js](../src/game.js) 的 `frame()` 里 `requestFrame(frame)` 在最后一行，
任何一次 `render`/`update` 抛异常都会让 rAF 链永久断掉——玩家看到的是"画面停住"，
控制台只有一行错误。

**抓到它的正是 E7 补的那条背景轨迹基线**：

```
not ok 1 - 背景绘制轨迹：白天与基线逐行一致
  error: 'R is not defined'
```

E7 当时加它的理由就是"整幅背景原本零防护"。两周不到，它还给了一个真 bug。

## 4. 两处修正

**D1 · 主循环加固。** `frame()` 改为 `try { … } finally { requestFrame(frame) }`。
一帧抛错也必须继续排下一帧。代价是持续出错时会逐帧刷错误——但那至少是可见的，冻死不是。

**D2 · 修正 E7 里一个不准确的判断。** E7 文档写"浏览器套件的轨迹只能记到
`drawImage([object HTMLCanvasElement])`，看不到背景本身画了什么"。本轮实测**这是错的**：
轨迹 harness 给 `CanvasRenderingContext2D.prototype` 打补丁，**离屏背景的绘制同样被记录**。
证据：改背景后 `play-day-l1` 与 `play-night-l4` 两条轨迹立刻变红，而 `menu`/`select-l3`/`quiz-l3` 一字未动。

## 5. 验收

| 项 | 结果 |
|---|---|
| `npm run verify` | **exit 0** |
| `npm test` | 189 / 189 |
| `test:browser` | 7 / 7 |
| 背景轨迹 | 白天 2907 → **9913 行**；夜间 3494 → **10524 行**（细节翻了三倍） |
| 浏览器轨迹 | 只有 `play-day-l1` 与 `play-night-l4` 变更，另外 3 条零改动 |
| `parity` | 3583 / 3583（移除 7 / 新增 85） |
| `dist` | 175.9 KB（原 172.3 KB） |

背景轨迹行数从 2907 涨到 9913，本身就是"细节密度"的一个客观度量。

## 6. 遗留

- 房屋窗户仍是平面蓝块，没有玻璃深度——下一轮可做。
- 角色（植物/僵尸）没有任何变化：它们才是"精细度"的另一半，但改动会触及
  `render-readonly`、实体绘制与 5 条轨迹，成本高于背景层。
- HUD 木条与卡片的细节未动。
