# E15 执行计划（画面精细度第二轮：窗户深度 + HUD 质感）

> 日期：2026-11-23
> 承接：[E14](工程执行计划-E14-画面精细度.md) 遗留清单的第 1、3 项。
> 性质：**美术迭代**。不改规则与逻辑。

## 1. 改了什么

| 位置 | 改动 |
|---|---|
| 窗户（`paintHouse`） | 玻璃内斜向反光（两片高光带）、框内四周投影、出挑窗台（亮面 + 底部投影）；花盆改为坐在窗台上、加了盆体侧面暗部 |
| HUD 顶栏（`drawSeedBank`） | 整条木板的竖直木纹（54 道，位置由确定性算术语给出）、下沿内阴影、投到草坪上的 20px 软影 |
| 卡槽卡片 | 内侧倒角（上亮下暗），让卡片有厚度 |

**一个渲染顺序的坑**：窗台最初写在花盆之后，结果把花盆压住了。窗台必须**先画**，花盆才有"坐上去"的关系。

**一个确定性的坑**：HUD 木纹不能用 `Math.random`——绘制轨迹是逐次调用的基线，随机位置会让每次跑出来的轨迹都不同，`test:browser` 永远红。改用 `(k * 13.7) % 736` 这类算术式定位。

## 2. 测量：加了东西，就得有数字

项目原则是「性能优化必须先有测量证据」；反过来，**加开销也该有数字**。用 `tests/helpers/scenario.mjs` 的记录型 ctx 直接量：

```
drawSeedBank 每帧调用数 : 2218
drawProgressBar         :   84
drawTopRightButtons     :   26
```

本轮给顶栏加的东西约 **60 次调用/帧**（54 道木纹 + 4 次填充 + 1 条渐变），
占 `drawSeedBank` 的 **2.7%**。空场整帧约 2700 次调用，也就是**整帧 +2.2%**。可以接受。

### 2.1 顺带发现一个更值得做的优化

`drawSeedBank` 的 2218 次调用**几乎全部来自 `drawPlantIcon`**——每帧把 8 张卡片上的植物各完整重画一遍。
这是全项目最大的单帧开销，也是分析报告里提过、但一直没测量的那一项。现在有数字了：
**把卡槽图标离屏预渲染一次**，这一项能砍掉接近 2000 次调用/帧。

本轮**没有做**这个优化（属于性能重构，不属于美术迭代），记入遗留。

## 3. 验收

| 项 | 结果 |
|---|---|
| `npm run verify` | **exit 0** |
| `npm test` | 189 / 189 |
| `test:browser` | 7 / 7 |
| 背景轨迹 | 9913 → **10015**（昼）、10524 → **10626**（夜），各 +102 行 |
| 浏览器轨迹 | 只有 `play-day-l1` / `play-night-l4` 与 `env.json` 变更；`menu` / `select-l3` / `quiz-l3` 零改动 |
| `parity` | 3636 / 3636（移除 4 / 新增 57） |
| `dist` | 178.8 KB（原 175.9 KB） |

**"哪三条没变"本身就是验证**：HUD 只在战斗场景绘制，所以菜单/选卡/答题三条轨迹必须一字不动。
它们确实没动，说明改动的影响面与设计意图一致。

## 4. 遗留

- **卡槽图标离屏预渲染**（有测量支撑，约 -2000 次调用/帧）。
- 角色精细度：植物与僵尸仍是扁平矢量，是"精细度"的另一半，但会触及实体绘制 + 5 条轨迹。
- 阳光盒、进度条、右上角按钮的内部质感未动。
