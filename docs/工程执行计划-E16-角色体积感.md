# E16 执行计划（画面精细度第三轮：角色体积感与接触阴影）

> 日期：2026-11-23
> 承接：[E15](工程执行计划-E15-HUD与窗户.md) 遗留清单的第 2 项（角色）。
> 性质：**美术迭代**。不改规则、数值与逻辑。

## 1. 先看

3 倍裁切下看菜单底部那一排（向日葵 / 豌豆 / 坚果 / 球球 / 僵尸同屏）。结论：

**问题不是"细节少"，是"硬描边 + 平涂填色"**——西装、衬衫、裤子都是纯色块，
配上 2~3px 黑边，整只僵尸像一张纸片。头部其实已经有径向渐变，躯干没有。

## 2. 改了什么

| 部位 | 改动 |
|---|---|
| 僵尸西装 / 衬衫 / 裤子 | 由纯色改为竖向渐变（左上亮、右下暗）；西装两片复用同一条渐变，省掉每只每帧一条 |
| 僵尸接触阴影 | 单层平涂 → 两层（外层大而淡、内层小而深），并向**右下**偏移 |
| 植物接触阴影 | 同上，统一光照方向 |
| 向日葵 | 花盘与花瓣之间加一圈根影，花盘不再"浮"在花瓣上 |

光照方向统一为**左上**，与 E14 在草坪上做的房屋投影、檐口投影一致。

## 3. 踩到的坑：渐变不能当颜色用

第一版我直接把 `C.suit` / `C.shirt` 换成了渐变对象。结果 `drawTorso` 里有一句

```js
let g = ctx.createLinearGradient(...);
g.addColorStop(0, C.suit);   // ← C.suit 现在是 CanvasGradient
```

抛 `Failed to execute 'addColorStop': The value provided ('[object CanvasGradient]')
could not be parsed as a color`，**每帧几百条**。

后果在画面上是"僵尸只剩一个灰方块"——绘制走到一半就抛异常。

**这次没有冻死游戏**，因为 E14 把 `frame()` 改成了 `try/finally`：
异常继续向上抛，但 `requestFrame` 照常排下一帧。修复方式是把纯色与渐变拆开：
`C` 保留纯色（继续做渐变停靠色），另开 `C.suitFill` / `C.shirtFill` / `C.pantsFill` 给填充用。

**这是 E14 那次加固第一次真正派上用场**：同一个 bug，在 E14 之前会表现为"游戏卡死"，
现在表现为"错误刷屏 + 画面缺一块"，两分钟就定位到了。

本轮只动了实体绘制，没动背景；而实体在菜单/选卡/答题/战斗四个场景里都出现。

## 5. 诚实的评价

这一轮的提升是**克制**的：僵尸有了体积感、阴影方向统一了、花盘坐进花瓣里了。
但角色的"扁平感"根源在**硬描边 + 简笔画轮廓**，那是美术风格本身。

要再上一个台阶，需要的是**改轮廓与细节密度**（比如给西装加褶皱、给僵尸加破洞、
给植物加叶脉），这会牵动 5 条轨迹与实体绘制的每一处坐标——属于"重画"而不是"调光"，
风险与主观性都高得多。

**建议先让人看一眼再决定**：这轮之后如果还是觉得"不够精细"，那问题大概率不在光影，
而在细节密度，需要一次明确的美术方向确认。

## 6. 遗留

- 卡槽图标离屏预渲染（E15 测得 `drawSeedBank` 每帧 2218 次调用，约 -2000 的空间）。
- 阳光盒 / 进度条 / 右上角按钮的内部质感。
- 角色细节密度（需要美术方向确认后再动）。
