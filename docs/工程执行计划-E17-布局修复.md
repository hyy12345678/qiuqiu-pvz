# E17 执行计划（两处布局硬伤）

> 日期：2026-11-23
> 起因：作者看过效果后说「还行，能接受」——画风到此为止，但我在早先的截图里发现两个
> **与审美无关的布局缺陷**，本轮只修这两处。
> 性质：**布局修复**。不改美术风格、不改规则。

## 1. 两个缺陷

| 位置 | 问题 | 为什么必须修 |
|---|---|---|
| 主菜单底部 | 「同人复刻 · 图形与音乐均为程序生成 · 仅供个人学习娱乐」是半透明深绿、无描边，**被僵尸的腿和脚压住，中段完全看不清** | 这是版权声明一类的文字，读不出来不只是难看 |
| 选卡页图鉴 | 13 张卡排成 **4+4+4+1**，最后一张孤零零挂在左下角，右侧空出一大片 | 看起来像做了一半 |

## 2. 改法

**菜单小字**：改成浅色填充 + 深色描边（`rgba(252,248,236,0.95)` / `rgba(24,34,14,0.85)`，
线宽 3）。无论底下是草地、僵尸还是按钮都读得出来，不需要额外压一层暗底。

**图鉴网格**：4 列改 **5 列（5+5+3）**，并且**每一行按自身宽度居中**，剩余量看起来才像有意为之。

调参过程：第一版 5 列直接用了原列宽 `cw=108 / gap=12`，5 列共 664px，
**把右侧的僵尸信息面板盖住了**（双发射手、小喷菇只露出一半）。
收到 `cw=104 / gap=8 / 起点 x=60` 后总宽 552px，排到 612，离面板还有 23px。

## 3. 验收

| 项 | 结果 |
|---|---|
| `npm run verify` | **exit 0** |
| `npm test` | 189 / 189 |
| `test:browser` | 7 / 7 |
| 浏览器轨迹 | **5 条全部变更** |
| `parity` | 3652 / 3652（移除 3 / 新增 9） |
| `dist` | 179.8 KB |
| 页面错误 | 0 |

**为什么 5 条轨迹全变**：轨迹从打开页面开始记，每条都要先经过主菜单。
只改了菜单与选卡两个场景，其余场景的轨迹仍会包含这两段，所以一起变——这是记录方式决定的，不是改多了。

## 4. 遗留

- 主菜单底部的角色与按钮仍有轻微重叠（球球挡住了报纸僵尸的一部分）。
  那是构图问题，动它会牵动整排角色的位置，判断为不值得。
- 选卡页网格下方仍有一片空白（行数从 4 降到 3 的必然结果），可以接受。
