# E19 执行计划（HUD 静态件离屏缓存：木板与太阳）

> 日期：2026-11-24
> 承接：[E18](工程执行计划-E18-图标离屏缓存.md) §7 的遗留。
> 性质：**性能优化第二轮**，先测量再动手。

## 1. 先测量，别再猜

E18 栽过一次：我按"图标占大头"的猜测去优化，实际只占 752/2218。

所以这轮先量单项：

```
drawSunIcon 卡内(0.34) : 82 次调用
drawSunIcon 大(0.85)   : 82 次调用
drawText 带描边        :  2 次调用
```

`drawSeedBank` 一帧画 9 个太阳（阳光盒 1 个 + 8 张卡各 1 个）→ **738 次**，正好是当时剩余 1466 的一半。
剩下的大头是木板本体：渐变 + 5 条贝塞尔曲线 + 54 道木纹 + 4 颗钉子，全部静态。

## 2. 改法

复用 E18 的 `hudSprite` 思路，在 `hud.js` 里加一个通用的离屏缓存（2 倍超采样）：

| 对象 | 原做法 | 现做法 |
|---|---|---|
| 木板 + 投影 + 钉子 | 每帧重建渐变、54 笔木纹、4 颗钉子 | 静态，缓存成 752×116 精灵，每帧一次 `drawImage` |
| 太阳图标 | 每次 10 次旋转 + 10 个三角 + 径向渐变 = 82 次 | 形状静态，缓存成 46×46 精灵，按 `s` 缩放贴出 |

**代价**：太阳不再随时间旋转（原来 `rotate(t*0.7)`）。
卡片上的太阳只有 0.34 倍（约 14px），看不出转速；阳光盒里那个 0.85 倍的大图标会失去缓慢旋转——**这是本轮唯一的可感知变化**。

## 3. 结果

| 项 | E18 后 | E19 后 |
|---|---:|---:|
| `drawSeedBank` 每帧调用 | 1466 | **452** |

**再省 1014 次/帧（−69%）。** 累计：2218 → 452，**−80%**。

这次和预估一致——因为单项是先量过的，不是猜的。

## 4. 踩到的两个坑

**① 变量被搬走了。** 我把木板的绘制整块挪进 `paintBankStatic()` 时，把 `let g` 也一起挪了进去，
但后面的阳光盒与卡片底色还在复用这个变量 → `g is not defined`，一次挂掉 12 条测试。

**② 测试用 drawImage 总数当"背景贴了几次"的代理，失效了。**
E18 之后卡槽图标走 drawImage，E19 之后木板与太阳也走，于是「恰好 1 次」变成 3、4 次。
修法不是放宽断言，而是**改成用 trace 精确数"整屏级"贴图**：

```js
e.op === 'drawImage' && e.args[1] === 0 && e.args[2] === 0 && e.args[3] === 1024
```

只有背景缓存是 `drawImage(画布, 0, 0, 1024, 640)`，精灵贴图都带各自的偏移与尺寸。
断言强度不降反升（从"数总数"变成"认得出哪一个"）。

## 6. 遗留

- 452 次里的构成已没有明显大头，再优化需要逐调用分析，收益递减。
