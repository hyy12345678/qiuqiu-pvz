# E24 执行计划（修铁门僵尸的投放节奏：晚出现、更常见、有提示）

> 日期：2026-11-24
> 起因：作者反馈「铁门僵尸在前期准备不足的情况下出来就直接杀穿了」。
> 性质：**投放节奏修正**——不是改强度，是改「什么时候出现、出现几次、玩家知不知道」。

## 1. 问题诊断

E23 把铁门的强度调到 8 株豌豆 21 秒能磨穿，数值上是合理的。
但作者仍然觉得"杀穿"——**问题不在强度，在节奏。**

实测（40 局）：

| 指标 | E23 原状 |
|---|---|
| 每局出现次数 | 2.1 只 |
| 首次出现 | **最早 66 秒** |

两个问题叠加：

1. **太早** —— 66 秒时玩家刚铺完第一排防线，经济还没起来，突然来个 600 盾的怪。
   这不是"策略挑战"，是"信息偷袭"。
2. **太少** —— 每局平均 2.1 只，整局也就见两次。**玩家没有机会学会怎么打它**，
   下次遇到还是手忙脚乱。

**合起来就是：既突然，又不熟。** 这是最坏的一种难度设计。

## 2. 三处改动

### 2.1 进度门槛（`waves.js`）

```js
const SPAWN_GATE = {
  screen: [0.55, +2],   // 进度 55% 之前权重归零，之后 +2
};
```

前半场完全不出，后半场才开始出现。玩家有完整的一局时间去布局。

### 2.2 提高权重（`levels.js`）

L3 / L4 的铁门权重 1 → 2。**从"偶尔来个怪东西"变成"后半场的常见压力"**。

### 2.3 首见提示（`sim.js`）

```
铁门僵尸来了！豌豆打不动，换火豌豆或炸弹！
```

用现有的 `waveText` 系统，但**加了字号参数**（26px）——原来的 `waveText` 是 46px 大字，
这句 20 字的话按 46px 会直接超出 1024 宽。

`world.seenTypes` 记录本局已登场的类型，只提示一次，换关重置。

## 3. 改后数据（40 局）

| 关 | 每局只数 | 首次出现 |
|---|---:|---|
| L3 | 2.1 → **3.2** | 66s → **221s**（中位 291s） |
| L4 | 1.8 → **2.7** | 67s → **251s**（中位 311s） |

**准备时间从 1 分钟变成 3.5 分钟**，出现次数从 2 次变成 3 次。

## 4. 新增测试（4 条）

[tests/screen-spawn-rhythm.test.mjs](../tests/screen-spawn-rhythm.test.mjs)：

| 测试 | 断言 |
|---|---|
| 不会在前半场出现 | 首次出现 ≥ 180 秒 |
| 后半场要够常见 | 每局平均 ≥ 2.5 只 |
| 首见弹提示且只弹一次 | `waveText` 含"铁门"，`seenTypes` 记录 |
| 普通僵尸首见不弹提示 | 一看就懂的不需要解释 |

## 6. 设计上的取舍

**我选择了"让它晚点来、来得更多"，而不是"让它变弱"。**

如果直接砍强度（比如削减从 25% 提到 50%），铁门就退化成"另一个铁桶"——
那这个僵尸就白加了。真正的问题是**信息不公平**，不是**强度太高**。

## 7. 仍未验证

- 221 秒这个门槛是否合适，取决于玩家在 3.5 分钟时能建起什么防线。**需要试玩。**
- 如果还是太早：把 `SPAWN_GATE.screen` 的 `0.55` 提到 `0.65`。
- 如果出现太频繁了：把 `+2` 降回 `+1`。
