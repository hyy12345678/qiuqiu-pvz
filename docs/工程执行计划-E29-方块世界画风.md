# E29：方块世界画风

> 起因：球球最近喜欢上了「我的世界」。作者决定在 3D 版上一步到位改成方块风，不做开关。
> 归档：改造前的 3D 版在 `archive/3d` 分支，2D 版在 `archive/2d` 分支。
> 范围：**只换画面，规则一行不动**。新敌人、挖矿、合成这些玩法放到下一轮。
> 原创约束：仓库是公开的，只借方块游戏的风格，所有贴图与名字都由代码现场画、自己起，不照搬任何官方角色、贴图与标志。

## 1. 做法

| 部分 | E28（圆润 3D） | E29（方块） |
|---|---|---|
| 角色几何 | 球、胶囊、车削、管、挤出叶片 | 只有长方体（少数十字交叉片：高草、花） |
| 角色颜色 | 顶点色 | **像素图集**：每个面一块像素画，顶点色只做染色 |
| 采样 | 线性 | 最近邻，无 mipmap |
| 尺寸单位 | 世界单位 | 像素：32 像素 = 一格宽 |
| 粒子 | 圆形软点 | 方形像素片 |
| 环境 | 棋盘草皮 + 草叶 | 草方块（带泥土侧面）、木板墙、原木柱、红砖台阶屋顶、木栅栏、树叶方块的树、石砖人行道、碎石路、萤石路灯、方形太阳 |
| 界面 | 琉璃面板 + 糖果按钮 | 切角面板 + 两像素斜面 + 黑框、方块按钮、硬投影文字、像素图标；大标题与播报用像素字 |

### 像素图集（`render/scene3d/atlas.js`）

方块风好看的前提是**纹素密度一致**：一个 8×8 的脸分到 8×8 的图集区域，一条 3×6 的胳膊分到 3×6。
放大以后每个像素在屏幕上一样大。实现是一张 1024² 画布 + 货架式打包，区域之间留 1 像素并外扩边缘，
避免最近邻采样串色。分配与绘制分离：Node 测试里没有画布，照样能算出每个面的 UV，几何体与浏览器里逐字节一致。

全部植物、僵尸、道具和布景建完后，图集用了约 410/1024 行。

### 方块零件（`render/scene3d/rig.js`）

`rig.box(节点, 材质类, [w,h,d] 像素, 中心, 面贴图)`。面贴图可以是带噪点的纯色、自定义像素画、
或 `'clear'`（全透明，给薄片的侧边用）。同节点同材质的零件仍然合并成一块网格，节点独立做动画，
所以原来的动画逻辑、受击闪白、护具分档、掉胳膊、死亡倒地全部保留。

### 像素字（`render/skin.js` 的 `pixelText`）

先用小字号（14–22px）画到离屏画布，读回像素、把半透明边缘二值化，再关掉平滑放大 3–5 倍。中文也能变成方块字。
只用于大标题、开场「准备 / 开始」、大波提示、暂停；正文仍用系统字体（像素字体放不进全部汉字），加一像素硬投影。

## 2. 性能

方块比圆润模型便宜：每个零件只有 12 个三角形，草叶从 3400 根换成 366 片十字交叉片。
CI 同款的软件光栅（SwiftShader，低配档）上，战斗画面从约 11fps 升到约 22fps。

## 4. 已知局限

- 像素字依赖 `getImageData`；Canvas 记录替身没有它，测试里走普通粗体字分支，像素字本身只在浏览器里被看到。
- 卡片肖像是 3D 渲染后缩小的，缩小时开着平滑，像素边缘会略软。
- 真机（iPad / 安卓）与 Safari、Firefox 仍未实测。
