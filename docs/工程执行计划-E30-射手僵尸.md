# E30 执行计划（新僵尸：射手僵尸）

> 日期：2026-11-26
> 起因：E29 之后游戏只有「方块世界」的皮，机制里没有一个角色在借用方块游戏的玩法语言。
> 这一期开始把「我的世界方向」的内容做进去——**第一个是远程敌人**。
> 性质：**新内容**。方块游戏里骷髅射手是每个人的童年阴影，这里做一只原创造型与命名的同类：
> 白骨配色的方块人，拿着一张像素弓，停在远处朝植物放箭。
> （E29 原则不变：只借方块游戏的风格与机制语言，贴图与名字全部原创。）

## 1. 设计：为什么是射手

现有 8 种僵尸（普通/旗帜/路障/铁桶/撑杆/报纸/铁门）全部是**近战接触**：要么走到植物面前啃，
要么靠护具硬吃火力。铁门改变的是「你带什么火力」，射手改变的是**方向**——
僵尸第一次能隔着几格地攻击你的后排。

> **射手僵尸停在中距离朝本行最靠前的植物放箭。**
> 植物的火力仍然够得着它（豌豆射程是整行），但它不走近；
> 它的价值不是冲到家门口，而是站在安全距离拆你的防线。

| 僵尸 | 玩家要做的 |
|---|---|
| 路障 / 铁桶 | 堆更多火力 |
| 撑杆 | 留空位或用坚果挡 |
| 报纸 | 注意破防后的狂暴 |
| 铁门 | 换一套火力配置 |
| **射手** | **让便宜的东西去接箭——坚果墙从「挡路」变成「挡箭」** |

反制关系（这是本期最重要的设计意图）：

- **坚果墙（50 阳光）**：箭命中的永远是本行最靠前的植物。把坚果放在射手那一行的最前，
  它 4000 血能接住七十多支箭，射手从威胁变成一台空转的靶机。
- **寒冰射手**：减速不只拖慢它的脚步，也拖慢放箭节奏（同一套 slowMul）。
- **土豆雷**：贴地的东西不接箭（和不会被啃是同一条理由）——它继续只干爆破一件事。

## 2. 数值

| 项 | 值 | 理由 |
|---|---|---|
| hp / speed | 200 / 16 | 本体是普通僵尸的底子：不是靠肉度存在，靠站位存在 |
| 射程 | 4.25 格（340px） | 站得够远拆防线，又不会远到植物打不着（豌豆射程是整行） |
| 一箭伤害 | 55 | 豌豆射手 300 血吃 6 箭（约 14 秒），是持续放血的威胁而不是秒杀 |
| 放箭间隔 | 2.4s | 与啃食（100/s）完全不同的伤害节奏，玩家听得出来 |
| 箭速 | 300px/s 向左 | 比豌豆慢一点，看得清轨迹 |

规则要点：

- 射手在「走路」状态下，一旦本行前方 4.25 格内**最靠前**有植物，切到 `shoot` 态停下；
- `shoot` 态每帧重算目标：目标死了/被铲了就回 `walk`（不存引用，不会悬挂）；
- 进入啃食距离时照常啃（`shoot` 态也查 `findEatTarget`）；
- 箭打进 `world.peas`，`type:'arrow'`、`vx:-300`。命中判定按「本帧越过植物右缘」，
  与火炬点燃豌豆同一条区间穿越语义；
- **箭不吃随机数**（不消耗 `world.rng`，命中粒子走 `fxRng`），除出怪权重外不动摇战斗随机流。

## 3. 实现

### 3.1 核心层

- `data/zombies.js`：`archer: { name:'射手僵尸', hp:200, acc:0, speed:16, ranged:true }`；
- `entities.js`：`spawnZombie` 补 `fireT:0` 字段（射击冷却，随 spawn 初始化，避免 undefined 运算）；
- `sim.js`：
  - `stepZombies` 走路分支尾部加射手判定；新增 `shoot` 状态分支（放箭、`slowMul` 生效于冷却）；
  - `stepProjectiles` 开头加 `arrow` 分支：越过植物右缘即命中，`potato` 例外，命中弹 `addPeaSplat(…,'arrow')` + `bulletHit` 音效；
  - `FIRST_SPAWN_HINT.archer`：首次登场喊话（E24 原则：改变打法的僵尸必须解释）；
- `waves.js`：`SPAWN_GATE.archer = [0.5, +1]`（前半场不出现，E24 的铁门先例）；
- `sfx.js`：新增 `arrow()`（弓弦绷响）。

### 3.2 渲染层

- `scene3d/zombies.js`：
  - `LOOKS.archer`：白骨配色（`skin:'#e6e2d2'`、无领带、破旧灰衣）；
  - `humanoid()` 的皮肤色改为 `L.skin || SKIN` 参数化——骷髅脸用黑眼窝精灵图，头顶不再画头发；
  - `buildBow(rig, pv)`：像素弓（两根斜置弓臂 + 握把 + 弓弦 + 搭在弦上的箭）挂在 `foreF`；
  - 动画：`shoot` 态抬臂拉弦，拉弓进度从 `fireT` 推导（**不加新字段**——冷却本来就是模拟层状态）；
- `scene3d/props.js`：`P.arrow` 弹丸原型（细长箭杆 + 箭头 + 尾羽，往左飞）；
- `scene3d/world-view.js`：主菜单阵容加一位射手（E22 踩过的坑：菜单阵容是写死的）。

### 3.3 界面层

- `scenes/select.js`：`TIPS.archer`；
- `scenes/help.js`：加一条「射手僵尸：停在远处放箭，用坚果墙挡箭」；
  16 行超出面板高度，行距 27 → 25、起点 62 → 60 收回。

### 3.4 关卡投放

| 关 | 是否出现 | 权重 |
|---|---|---|
| L1 / L2 | 否 | — |
| L3 | 是 | 2（实测 1 时 40 局有 8 局空手，见 4.1） |
| L4 | 是 | 2 |

与铁门同一天条：L3 起步、进度门槛 0.5，先「明确登场」再「反复出现」。

## 4. 护栏与验收的预期

- 出怪池加类型不改变 `pickType` 的 rng 消耗次数，但类型选择会移动 →
  依赖整局随机流的测试（screen-spawn-rhythm 的区间断言等）重跑确认；
- 浏览器轨迹基线只锁 L1 早期与 L4 前 4 秒（首个怪 26s 后才出），
  **预期不需要重盖章**；若意外变红，逐行审差异后再批；
- 新增 `tests/zombie-archer.test.mjs`（规则钉子 + 投放节奏），测试条数只增不减；
- 全链按既有次序收口：`npm test` → `fingerprint:update` → `parity:rebase` → `build` →
  `test:smoke` → `test:browser:baselines` → `verify`。

### 4.1 实测中的两处偏差（都已修正）

1. **L3 权重 1 → 2**。实测 40 局有 8 局一只射手都不来（平均 1.6 只）——
   和 E24 批评铁门的措辞一字不差："偶尔来个怪东西"玩家学不会。
   提到权重 2（门槛加成后后半场等效 3），实测 40/40 局都有、每局平均约 3 只。
2. **浏览器轨迹基线有一条按预期外变红：menu**。原因不是战斗，而是选关卡片——
   卡面按 `lv.types` 画僵尸头像行，L3/L4 各多了一种头像，间距从 34.8px 重排到 29px。
   逐行审过：menu 基线 685 → 687 行，差异恰好是 L3/L4 两张卡的头像行重排，
   day-l1 / night-l4 两条逐字节未动。审查通过后 `test:browser:update` 重新盖章。
   （先前的"预期不需要重盖章"判断漏了菜单卡片也读关卡表——记在这里。）

## 6. 未验证 / 遗留

- 平衡未实测：2 只射手同时盯同一行的拆防速度，需要真人试玩。
  旋钮：箭伤 55、间隔 2.4s、射程 4.25 格，三个都在 `sim.js` 顶部常量区。
- 射手与铁门不叠加（一个僵尸一种手段）；「铁门射手」是更大的改动，不做。
- 选关界面的僵尸预告面板 8 格已满，L4 的夜战提示行会被挤出——
  夜战规则已由关卡标题与操作说明覆盖，接受这处取舍。
