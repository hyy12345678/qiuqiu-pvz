# 球球的植物大战僵尸 · E4 执行计划（植物绘制表驱动）

> 日期：2026-11-20
> 上游依据：[docs/项目分析-2026-11-20.md](项目分析-2026-11-20.md) §5.2「两套 switch 必须手工同步」、§9 P1-6。
> 本轮性质：**纯结构重构**。画面必须逐像素不变。
> 放行条件：5 条绘制轨迹基线**一字未改**的前提下 7/7 绿。

## 1. 问题

[src/render/plant.js](../src/render/plant.js) 里有两个各 13 个 case 的 `switch`：

- `drawPlantEntity` 用实体的实时字段（`phase` / `recoil` / `hp` / `fuse` / `asleep` / `lifeT`）画战场上的植物；
- `drawPlantIcon` 用一组写死的相位（`1`…`12`）画图鉴、卡槽与种子栏的图标。

两者都必须覆盖 `PLANTS` 的全部 13 个种类。**漏掉一个 case 不会报错、不会告警**：
实体是"种下去地上空的"、图标是"图鉴里那一格白的"。新增迪迦时就得同时改两处。

## 2. 决策记录

**D1 · 合并成一张表 + 一张姿态表，而不是抽公共参数函数。**
`PLANT_DRAWERS` 统一签名 `(t, pose) => void`；实体直接传自身，图标传 `ICON_POSE[type]` 的固定姿态。
没有选"给每个绘制函数加默认参数"或"实体合成一个假对象"，因为那会把 13 种植物的字段依赖藏在调用点之外，
看起来更短、实际更难读。

**D2 · 图标的相位数字原样搬进 `ICON_POSE`，不做重新设计。**
本轮是结构重构，不是美术调整。`ICON_POSE` 里每个字段都能和原 case 逐项对上（见 §4.1），
包括 `tiga` 的 `lifeT/maxLifeT = 0.85` 与 `wallnut` 的 `hp/maxHp = 1` 这种"拐了个弯的常量"。

**D3 · 漏登记由测试兜住，而不是靠 `if(draw)` 的静默跳过。**
绘制表本身保留 `if(draw)` 守卫（运行时拿到未知类型不应该崩），但新增
[tests/render-plant-table.test.mjs](../tests/render-plant-table.test.mjs) 四条断言把它变成红灯：
每个 `PLANTS` 键必须有抽屉与姿态、表里不能有死条目、`PLANT_ORDER` 同集合、每个图标**必须真的落笔**。

最后一条是关键：它实际调用 `drawPlantIcon` 并统计 `fill`/`stroke` 次数，
所以"抽屉存在但不画东西"也会被抓到，而不只是"键存在"。

## 4. 验收

### 4.1 parity 差异逐行核对（盖章前）

`node scripts/check-parity.js --rebase --verbose`：**移除 30 行 / 新增 34 行**。

移除的 30 行 = 13 个实体 case + 13 个图标 case + 2 个 `switch(...)` + 2 个收尾 `}`。
新增的 34 行 = 13 个抽屉 + 13 个姿态 + 2 个 `const draw = …` + 2 个 `if(draw) …` + 2 个表头 + 2 个表尾。

逐项抽查（左边是原 case，右边是新表项）：

| 原 | 新 |
|---|---|
| `case 'wallnut': drawWallnut(1, t, 5); break;` | `wallnut: { phase:5, hp:1, maxHp:1 },` |
| `case 'cherry': drawCherry(0.9, t, 7); break;` | `cherry: { phase:7, fuse:0.9 },` |
| `case 'puff': drawPuff(t, 9, false); break;` | `puff: { phase:9, asleep:false },` |
| `case 'tiga': drawTiga(t, 12, 0, 0.85, 0); break;` | `tiga: { phase:12, recoil:0, lifeT:0.85, maxLifeT:1, flash:0 },` |
| `case 'sunshroom': drawSunshroom(t, p.phase, p.asleep); break;` | `sunshroom: (t, p) => drawSunshroom(t, p.phase, p.asleep),` |

### 4.2 结果

| 项 | 结果 |
|---|---|
| `npm test` | **172 / 172**（168 + 4 条新覆盖测试） |
| 5 条绘制轨迹基线 | **零更新，逐字节一致** |
| `npm run test:browser` | **7 / 7** |
| `npm run verify` | **exit 0** |
| `parity` | 3441 / 3441 |
| `fingerprint` | 39 / 39，变化 1 个文件（`src/render/plant.js`） |
| `dist` | 171.3 KB |

**"轨迹零更新"是这一轮的强证据**：`select-l3` 会画满整页 13 张图鉴卡，`play-day-l1` / `play-night-l4`
会画战场实体。若任何一个图标姿态的相位、任何一条实体分支的取值与原 switch 不同，
这 5 条基线不可能全部保持字节一致。

### 4.3 收益

- 新增一种植物：**从"改两处 switch（漏一处不报错）"变成"在两张表里各加一行 + 测试会告诉你漏了"**。
- `drawPlantEntity` 34 行 → 12 行；`drawPlantIcon` 22 行 → 9 行。
