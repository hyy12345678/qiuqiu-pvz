# 球球的植物大战僵尸 · E5 执行计划（僵尸绘制拆分）

> 日期：2026-11-20
> 上游依据：[docs/项目分析-2026-11-20.md](项目分析-2026-11-20.md) §5.2「`drawZombieEntity` 单函数画完 6 种僵尸 × 多种状态」、§9 P1-8。
> 本轮性质：**纯结构重构**。画面必须逐像素不变。
> 放行条件：5 条绘制轨迹基线**一字未改**的前提下 7/7 绿。

## 1. 问题

[src/render/zombie.js](../src/render/zombie.js) 的 `drawZombieEntity` 是全项目最大的函数：**309 行**。
一个函数里按顺序画完「阴影 → 后臂 → 腿 → 躯干 → 领带 → 前臂 → 杆 → 旗 → 头 → 脸 → 头饰 → 报纸 → 暴怒 → 冰霜」，
并且头上挂着 13 个派生量（`swing`/`bob`/`armSway`/`mouth`/`lunge`/`angry`/`reading`/`slowed`…）。

后果：改某个配件（比如铁桶的描边）要在 309 行里先定位，且没法单独确认"这段只影响铁桶"。

## 2. 决策记录

**D1 · 片段函数共享 ctx 变换，只通过 `pose` 传派生量。**
所有片段都画在"调用方已经 `translate` 到脚下"的坐标系里，因此片段签名里**没有 ctx、没有坐标**，
只有一个 `pose` 对象。不采用"每个片段自己 `save/translate/restore`"——那会引入 11 组额外的变换调用，
既改变绘制调用序列（轨迹会红），也改变了坐标系的语义。

**D2 · 守卫式提前返回，保持"条件满足才画"的语义。**
原代码用 `if(angry){ … }` 包裹；拆成片段后片段的整个函数体就是那个块，
所以写成 `if(!p.angry) return;`。逻辑等价（德摩根），且比把 43 行再缩进一层更好读。

**D3 · `pose` 里不放 `z` 本身。**
头饰、杆、旗需要读 `z.type` / `z.poleLost` / `z.state` / `z.eatT`，这些作为独立参数传，
而不是把整个实体塞进 `pose`。理由是保持"绘制不接触世界状态、只接触它要用的字段"这条既有契约
（文件头第一行就是这个意思）。

## 4. 验收

### 4.1 parity 差异逐行核对（盖章前）

`node scripts/check-parity.js --rebase --verbose`：**移除 23 行 / 新增 55 行**。

移除的 23 行分三类，全部有对应：

| 类别 | 例 | 去向 |
|---|---|---|
| 变量改名（14 行） | `ctx.beginPath(); ctx.arc(-47,-61+armSway,5,0,TAU);` | `…+p.armSway…`（`pose` 前缀） |
| 守卫改写（6 行） | `if(angry){` | `if(!p.angry) return;` |
| 派生量提升（3 行） | `const tieWave = Math.sin(at*3.1)*2;` | `const tieWave = Math.sin(p.at*3.1)*2;` |

新增的 55 行 = 11 个函数声明 + 6 个 `const C = p.C;` + 2 个 `const draw…`? （无）+ 10 个片段调用 + `const pose = {…}` + 改名后的对应行 + 收尾 `}`。

**关键结论：差异中没有出现任何一个绘制常量或坐标数字的变化。** 比对左右两侧可以看到，
所有数值（`-47`、`-61`、`4.2`、`8.5`、`0.62`…）逐字相同，变的只有变量前缀与块结构。
