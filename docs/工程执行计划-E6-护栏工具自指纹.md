# 球球的植物大战僵尸 · E6 执行计划（护栏工具自指纹）

> 日期：2026-11-20
> 上游依据：[docs/项目分析-2026-11-20.md](项目分析-2026-11-20.md) §7.3 第三条硬伤「护栏本身没有护栏」、§9 P1-7 的剩余部分。
> 本轮性质：**工具收口**。`src/**` 零改动，画面与规则不变。

## 1. 问题

`npm run fingerprint` 只走 `src/**`。这意味着：

- 有人把 `check-parity.js` 改成恒真，跑一遍全绿，**没有任何检查会发现**；
- 有人把 `check-fingerprint.js` 的扫描目录改小，同样无声无息；
- `scripts/`、`tests/`、`package.json`、`headless_test.js` 全部在护栏之外。

对一个把"可验证"当核心承诺的项目来说，这是最讽刺的一条：**证明工具自己没有被证明。**

## 2. 决策记录

**D1 · 加第二份清单，不动第一份。**
`src/**` → `scripts/source-fingerprint.txt`（原有，语义不变）；
`scripts/**` → `scripts/tool-fingerprint.txt`（新增）。
没有把两份合并成"全仓一份清单"，理由是：`tests/` 是**应该自由变化**的区域，
把它哈希进去会让每次改测试都要重盖，而重盖越频繁，人就越是无脑盖章。
`scripts/` 不同——它是决定"什么算绿"的权力机关，应当冻结。

**D2 · 排除 `scripts/*.txt`。**
三份基线（`parity-baseline.txt` / `source-fingerprint.txt` / `tool-fingerprint.txt`）都住在 `scripts/` 里。
把它们哈希进自己的清单会形成自指：每次重盖都改变被哈希的内容，永远对不上。
因此 `buildManifest` 增加一个**可选 filter**，只影响"哪些文件进清单"，不改变路径口径与排序。

**D3 · 一条命令校验两份，不拆成两条 npm 脚本。**
`npm run fingerprint` 现在输出两行，任一行红了整体就红。
拆成 `fingerprint:src` / `fingerprint:tools` 会让 `verify` 少跑一条就成了新的静默缺口。

**D4 · 仍然不覆盖 `tests/`，但补了三条测试兜住清单本身。**
见 §4.2。覆盖 `tests/` 的代价（每次改测试都要盖章）大于收益；
真正的高危动作是"改工具让检查恒真"，D1 已经堵住。

## 3. 改动

| 文件 | 改动 |
|---|---|
| `scripts/check-fingerprint.js` | `walk`/`buildManifest` 增加可选 filter；`main` 改为遍历两份清单；新增 `TOOL_BASELINE` |

| `README.md` | 命令表补第二份清单的说明 |

## 4. 验收

### 4.1 真实篡改验证（不是模拟）

在 `scripts/dev.js` 末尾追加一行注释后跑 `npm run fingerprint`：

```
TAMPERED_EXIT=1
  PASS —— 没有未登记的源码变化
  FAIL —— 发现未登记的护栏工具变化
    ~ 内容变化: dev.js
```

`git checkout -- scripts/dev.js` 还原后再跑：

```
CLEAN_EXIT=0
  PASS —— 没有未登记的源码变化
  PASS —— 没有未登记的护栏工具变化
```

这是本轮最直接的证据：**改动护栏工具现在会红，改回来就绿。**

### 4.2 新增测试

| 测试 | 断言 |
|---|---|
| 护栏工具清单覆盖 `scripts/**` 且排除 `*.txt` 基线 | 条目数 ≥7、无 `.txt`、含 `check-fingerprint.js` 与 `check-parity.js` |
| filter 只筛文件，不改变路径口径与排序 | 在临时目录造 `a.js`/`b.js`/`notes.txt`，过滤后仍按路径排序、同条目哈希一致 |
| dry-run 不写基线（原有，已加强） | 两份基线文件字节都不变 |

### 4.3 全链

| 项 | 结果 |
|---|---|
| `npm run verify` | **exit 0** |
| `npm test` | **174 / 174**（172 + 2 条新测试） |
| `parity` | 3473 / 3473（`src/**` 未动，无需重盖） |
| `fingerprint` | 源码 39/39 **PASS** + 护栏工具 7/7 **PASS** |
| `test:browser` | 7 / 7 |
| `dist` | 171.8 KB，**未变**（源码摘要只覆盖 `src/**`，本轮没动 src） |

### 4.4 一个附带的好性质

`srcDigest`（构建戳用的摘要）仍然只覆盖 `src/**`，因此**改工具不会让 dist 失效**。
本轮 `dist` 一个字节都没变，`parity:dist` 也没红——这正是 D1「分开两份清单」带来的好处。

## 5. 遗留

- `tests/**` 仍未进指纹（D4 已说明理由）。若要防"删测试换取绿"，更合适的做法是
  "测试数量下限"这类显式断言，而不是全量哈希；留给后续评估。
- `parity` 与 `fingerprint` 的职责重叠仍未处理：`parity` 保的是"行内容增删"，
  `fingerprint` 保的是"任何字节变化"，前者是后者的真子集。是否退役 `parity` 需要单独一轮论证，
  因为它同时承担着"搬家阶段逐行溯源"的历史价值。
