# 球球的植物大战僵尸 · E7 执行计划（战斗背景拆分 + 背景轨迹基线）

> 日期：2026-11-20
> 上游依据：[docs/项目分析-2026-11-20.md](项目分析-2026-11-20.md) §5.2「`paintBattleBG` 昼夜两套背景硬编码」、§9 P1-8 的后半。
> 本轮性质：**结构重构 + 补一条缺失的回归防护**。画面必须逐像素不变。

## 1. 问题

`paintBattleBG`（[background.js](../src/render/background.js)）221 行，一个函数里按顺序画完天空、树丛、栅栏、草坪、
棋盘格、草丛、入场暗区、整栋房子、泥土带、底部草地，再在 `if(night)` 里盖一遍夜色、星空、月亮、雾气、窗光、壁灯光晕。

更值得注意的是**它没有任何回归防护**。做这一轮时才发现：

- 背景是整幅预渲染后缓存进离屏画布的（`bgCache`），浏览器套件的轨迹只能记到 `drawImage([object HTMLCanvasElement])`；
- `tests/render-background.test.mjs` 的 4 条测试全部在测**缓存行为**，没测一笔绘制内容；
- 浏览器冒烟用的是「画面有没有变化」的哈希比较，不是与基线比。

**结论：E7 之前，全项目最大的一张图（整幅战斗背景）改了也不会有人发现。**

## 2. 决策记录

**D1 · 先补防护，再动手改。**
顺序是：写出背景轨迹记录器 → **用 E7 之前的代码生成基线** → 再拆函数 → 要求新代码产出逐行相同的轨迹。
这样基线的来源是"被证明等价的旧代码"，而不是"我刚写的代码"，否则等于自己给自己盖章。

**D2 · 轨迹记到 Canvas 调用级，不记像素。**
与浏览器轨迹口径一致：方法名 + 参数（数字保留 3 位小数）+ 属性写入，渐变按创建顺序编号。
理由：像素摘要只能告诉你"变了"，调用级轨迹能告诉你"第 1842 行 `arc` 的半径从 5.2 变成 5.3"。
在 Node 里也不需要真实 Canvas，跑得快（毫秒级）。

**D3 · 拆分只按绘制区域切，不按行数切。**
七个片段：天空 / 草坪 / 入场暗区 / 房屋 / 泥土带 / 底部草地 / 夜色。

**D4 · 随机流的消耗顺序是硬约束。**
`paintBattleBG` 用 `mulberry32(20260814)` 逐次取值决定每一丛草、每一颗星的位置。
片段之间共享同一个 `R`，**调用顺序就是 R 的消耗顺序**——调换任意两个片段，整张背景会重排。
这条写进了 `paintBattleBG` 的函数头注释。

**D5 · 房屋的纵向范围提成模块常量。**
`y0`/`y1` 在房屋段与夜色段（壁灯光晕、窗光）都要用，原实现把 `y0` 定义在房屋段、夜色段直接引用。
拆成两个函数后这个隐式共享必须显式化，否则夜色段会拿到 `undefined`、壁灯光晕画到 `NaN` 坐标上。
因此提成 `HOUSE_Y0` / `HOUSE_Y1`。

## 4. 验收

### 4.1 背景轨迹：用旧代码生成基线，新代码逐行一致

```
# 从 HEAD（E7 之前）的 background.js 生成
UPDATE_BG_TRACE=1 node --test tests/render-background-trace.test.mjs
  → background-day.trace.txt    2907 行
  → background-night.trace.txt  3494 行

# 换回 E7 之后的代码，逐行比对
node --test tests/render-background-trace.test.mjs
  ok 1 - 背景绘制轨迹：白天与基线逐行一致
  ok 2 - 背景绘制轨迹：夜间与基线逐行一致
```

**6401 行绘制调用逐行相同**，包括每一个 `arc` 半径、每一处渐变停靠点、每一次 `fillRect` 的坐标。
这比"逐像素"更强：它同时证明了 R 的消耗顺序没变（顺序一变，第 n 次取值的用途就变，整串都对不上）。

### 4.2 parity 差异逐行核对（盖章前）

`node scripts/check-parity.js --rebase --verbose`：**移除 4 行 / 新增 30 行**。

移除的 4 行：

| 移除 | 去向 |
|---|---|
| `const y0 = LY-34, y1 = LY+ROWS*CH+4;` | 提成模块常量 `HOUSE_Y0`/`HOUSE_Y1` |
| `g = ctx.createLinearGradient(0,LY+ROWS*CH,0,H);` | 改为 `const g = …`（片段内自己声明） |
| `g = ctx.createLinearGradient(LX+COLS*CW, 0, W, 0);` | 同上 |
| `if(night){` | 改为 `if(night) paintNight(R);` |

新增的 30 行全是结构件：7 个函数声明、4 个 `let g;`、6 个收尾 `}`、5 个调用、2 个房屋常量、2 个 `y0` 声明、2 个 `const g`、1 个 `if(night)`。

**没有任何一条绘制语句被增删改。** 200 多条绘图行在多集合里完全对齐。
