# E9 执行计划（测试清单下限 + 考古附录）

> 日期：2026-11-20
> 上游依据：[护栏评估 E8](护栏评估-E8-parity与legacy去留.md) §3.3 与 §5。
> 本轮性质：**补防护 + 收尾文档**，`src/**` 零改动。

## 1. 补的洞：`tests/` 没有防护

E8 的结论是「`tests/**` 不进 fingerprint」，理由正当（改测试是常态，全量哈希会训练人无脑盖章），
但留下一个没人管的缺口：**删掉测试让 CI 变绿，原本不会有任何检查发现。**

「加一个测试数量的下限」是 E8 里写下的方向。本轮把它做出来。

## 2. 决策记录

**D1 · 清单放在 `scripts/test-inventory.json`，不是 `.txt`。**
这是整个设计的关键：E6 的工具指纹排除了 `scripts/*.txt`（避免基线自指）。
因此只有非 `.txt` 的文件才会被工具指纹保护——**想调低下限，必须先过 `fingerprint` 那一关**。
如果当初顺手写成 `test-inventory.txt`，这个机制会静默失效。这是 E6 的排除规则第一次产生实际后果。

**D2 · 下限语义，不是精确匹配。**
加测试永远不用重盖；只有「文件消失」或「某文件用例数减少」才红。
精确匹配会让每次加测试都要重盖工具指纹，正是 D1 想避免的摩擦。

**D3 · 只数 `test(` 声明，不数运行时用例数。**
运行时条数会被循环放大（`render-baseline` 一条声明跑出五条用例），作为下限指标不稳定。
声明的分辨率对「有没有人删测试」已经足够。
已知口径：同行内写在 `describe(...)` 之后的 `test(` 不计数；代码库中不存在这种写法，
这条口径由测试钉住，不静默。

**D4 · `test:inventory` 独立进 `verify` 链，尽管 `npm test` 已包含它。**
原因：如果只靠测试文件自身，删掉 `tests/test-inventory.test.mjs` 就等于把守卫一起删了。
独立成一条命令后，删这个文件会让 `verify` 在 `test:inventory` 处直接红。

## 3. 同时补的文档债

E8 写了「`parity:legacy` 应降级为考古附录」，但当时**没有真的改 README**。本轮补上：

- 命令表里 `parity:legacy` 从 `parity` 那一行拆出来，单独标明「考古工具，不是绿灯护栏」；
- 原「重构前的基线在哪里」一节改名为「考古附录」，并写明它现在还值什么。

顺带修正了一处 E1 之后就过期的描述：命令表里 `verify` 的顺序还写着
`test → build → parity:dist`，而实际早已是 `test → parity:dist → build`。

## 4. 验收

### 4.1 负向验证（真实删除）

```
rm tests/live-binding.test.mjs
  → DELETED_EXIT=1
    FAIL —— 测试清单比下限少
      - 测试文件消失: tests/live-binding.test.mjs（下限 1 条）
      合计：下限 182 条 / 当前 181 条

还原后
  → RESTORED_EXIT=0
    PASS —— 没有测试被删除或减少
```

### 4.2 全链

| 项 | 结果 |
|---|---|
| `npm run verify` | **exit 0** |
| `npm test` | **180 / 180**（176 + 4 条清单测试） |
| `npm run test:inventory` | 下限 182 条 / 当前 182 条，30 个文件，**PASS** |
| `fingerprint` | 源码 39/39 + **护栏工具 9/9**（新增 `check-test-inventory.js` 与 `test-inventory.json`） |
| `parity` / `parity:dist` / `dist:fresh` | 全部 PASS，`dist` 未变（本轮不动 src） |

### 4.3 新增测试（4 条）

| 测试 | 断言 |
|---|---|
| 总数不得低于下限 | 真实仓库数据 vs `test-inventory.json` |
| 下限只拦减少、不拦新增 | 合成数据：加文件、加用例都应 PASS |
| 删文件与减用例都会被抓到 | 合成数据：`removed` 与 `shrunk` 分别命中 |
| 计数只认行首 `test(` | 注释、字符串、同行 `describe(...)` 后面的都不计数 |

## 5. 现在的护栏全貌

| 层 | 覆盖 | 进 `verify` |
|---|---|---|
| `parity` 行快照 | `src/**` 行内容增删（改动审计） | 是 |
| `fingerprint` 源码 | `src/**` 任何字节变化 | 是 |
| `fingerprint` 工具 | `scripts/**` 任何字节变化 | 是 |
| `test:inventory` | 测试只增不减 | 是 |
| 背景轨迹 ×2 | 整幅战斗背景的绘制调用 | 是（在 `npm test` 内） |
| 浏览器轨迹 ×5 | 五个场景的绘制调用 | 是 |
| `dist:fresh` | 产物是否随源码提交 | 仅 CI |
| `parity:legacy` | 重构前基线溯源 | **否**（考古） |

## 6. 遗留

- `tests/` 仍然只受「数量下限」保护，不受「内容」保护：把一条断言改弱不会被发现。
  真要解决，得让测试内容有可审计的摘要，代价与 E6 的结论冲突（改测试是常态）。
  当前判断：数量下限 + 评审是性价比最高的一档。
- `src/` 剩余长函数都在 100~140 行区间，属于内聚单元，不再拆。
