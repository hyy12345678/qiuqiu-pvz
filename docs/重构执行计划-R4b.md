## 1. 接口与职责

| 模块 | 接口 | 职责 |
|---|---|---|
| `src/ui/input.js` | `toCanvas(canvas, event)` | 客户区坐标经画布矩形转换为 1024×640 逻辑坐标，不乘 DPR。 |
| 同上 | `bindInput({ canvas, document, window, world, ui, onPress, onKey })` | 绑定原有鼠标、触屏、手势、右键与键盘事件；更新悬停和光标、右键清选择；按下与键盘规则交给回调。 |
| `src/game.js` | `createGame({ world, ui, frameState, audio, render, now, requestFrame })` | 实例化调度与循环闭包，不在导入或创建时启动浏览器副作用。 |
| 返回对象 | `dispatch(action)` | 原有限 switch，不增加通用命令系统或新动作。 |
| 返回对象 | `handlePress(point)` | 音频唤醒、热点、阳光、格子的优先级与规则转发。 |
| 返回对象 | `handleKey(key)` | 保留原键盘条件、选卡与音频差异。 |
| 返回对象 | `start()` | 读取初始时钟并排第一帧；装配层只调用一次。 |
| `src/main.js` | 装配 | 创建种子、ports、world、ui、渲染帧状态，绑定画布，注入 SFX/render/时钟/rAF，绑定输入，再启动。 |

`game` 不直接读取 DOM、存储或音频单例；真实渲染函数与平台能力均由装配层传入。`ui/input` 不导入 game、render、audio 或核心动作；只负责设备适配和界面状态。无需新增停止/重启、多实例并发绘制或全局事件总线。

## 2. 必须保留的行为

- `mousemove` 更新鼠标、悬停和光标；普通 `mousedown` 只按下，不顺便刷新悬停。右键按下忽略，中键沿用可按下行为。
- `touchstart` 先 `preventDefault`，取 `changedTouches[0]`，先移动再按下；touchmove 只移动，touchend 只阻止默认行为。三者均保留 `passive:false`；gesturestart 和 contextmenu 保留 preventDefault。
- 光标：命中热点优先 pointer，其次选卡/铲子 crosshair，否则 default；热点从后往前命中。
- 每次按下都先 `ensure → resume` 音频，再写鼠标位置。先热点，再判断战斗/暂停，再收阳光，再尝试格子动作。
- 点击阳光只启动飞行动画，不立即到账；飞行中的阳光不抢占格子点击。
- 键盘仅在 play 状态生效。1–8 要求槽位存在且未暂停；Esc 暂停时仍可清选择；P/p 切换暂停；M/m 只切换音乐，不额外 ensure、resume 或 click。
- 按钮 music 与键盘 M 不合并：按钮按动作的 ensure 字段唤醒音频，切换后发 click。空队伍 startQuiz 仍只发 error。
- `dt=(now-last)/1000` 后先更新 last，再 `Math.min(dt,0.05)`，不增加固定时间步、下界裁剪或追帧。
- 每帧先推进渲染时钟并同步音乐状态，再更新 play/quiz，再 render，最后排下一帧。菜单、暂停和胜败仍绘制并推进渲染时钟；暂停不推进战斗。
- quiz 更新进入 play 的那一帧不额外调用 updatePlay。rAF 时间原点在输入绑定后、start 时读取，保持原启动顺序。

## 5. 重新盖章规则

1. 先对比 R4a 源码，确认只有移动、显式形参、平台回调注入与冒烟驱动改接。
2. 全部单测、源码冒烟、真实浏览器与 5 条绘制轨迹比较通过；不使用 UPDATE_TRACE。
3. 对 input/game 关键语句分别做临时副本变异，证明测试能失败，不污染当前源码。
4. 审计 parity 后执行 parity:rebase 与 fingerprint:update，再跑 npm run verify。
5. 检查渲染/核心/音频/存档源码与轨迹文件不变；R4a 的既有未提交改动必须保留。

### 7.1 迁移核对

以保存的 R4a 源码而非 Git HEAD 提取 dispatch、handleMove、handlePress、keydown 回调与 frame 函数体。
仅进行 `G→world`、`UI→ui`、`SFX→audio`、`cv→canvas`、`e.key→key`、帧参数 `now→timestamp`、
`requestAnimationFrame→requestFrame` 等明确替换并忽略空白后，五组函数体一致。
源码冒烟仅把按下驱动接到实际注册的 mousedown；未弱化原 A–I 断言，发布物没有新增测试出口。

### 7.2 红灯验证

全部在临时目录副本中实施；七项均触发预期失败，原工作区源码 SHA-256 未变。

| 变异 | 检出 |
|---|---|
| 横向坐标比例 W 改为 H | 输入坐标、悬停与触屏一致性失败。 |
| touchstart 先 onPress 后 handleMove | 输入 6 的回调状态与顺序失败。 |
| passive:false 改 true | 输入 2 的监听选项断言失败。 |
| 删除 dt 的 50ms 截断 | 调度的 play 与 quiz 时间断言失败。 |
| 删除 frame 末尾 requestFrame | 继续且只排一个回调的断言失败。 |
| 暂停返回移到热点命中之前 | 调度 9 的暂停热点优先级失败。 |
| 键盘 M 改走 music 按钮 dispatch | 调度 12 检出多余 click 音效。 |

### 7.3 真实浏览器补充

- 启动开发服务器，以 Playwright 操作未经测试改写的页面；视口 768×640、DPR=2、触屏模拟，核对画布 backing 宽度为 2048。
- 空队伍不可开始；选卡再删除最后一张后恢复禁用。触屏选卡、开始、连续答题后进入战斗。

- 检查暂停、种植与铲除截图；同时发送 M/m、P/p、Esc。无页面错误、控制台错误或外部请求。

### 7.4 边界与后续

- 记录型事件目标验证监听回调与顺序，不等于手机真机手势测试；手动 rAF 验证列明的调度情况，不证明全部浏览器时序。
- 静态边界扫描不是完整 JavaScript 解析器；受控绘制轨迹与未经测试改写的发布冒烟为两条独立验证路径。
- 源码冒烟仍部分依赖打包后的内部命名，R5 再全面迁移；本轮没有借机改动测试架构。
- 真机触屏、字体、真实音频与手感由用户人工验收，清单未代勾。
