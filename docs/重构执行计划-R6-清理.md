## 2. 本轮边界

- **不碰 `src/**`**，不改数值、玩法、绘制顺序与随机流；`dist/` 标准产物必须继续逐字节不变（以 `parity:dist` 与 `git status dist` 证明）。
- **不碰受控轨迹基线**：5 条轨迹继续使用现值，不使用 `UPDATE_TRACE`。

- **删除动作逐条待你确认后才执行**（方案 §6 R5 项 5 的硬要求）；本计划先给事实与选项。

### 7.4 记录到的语义差异

- `node headless_test.js`（不带参数，即 legacy 目标）现在在 `beginPlay` 处抛
  `TypeError: Cannot read properties of undefined (reading 'night')`，比文件头注释原先写的
  「在场景 D2 失败」更早。这与 legacy 目标已不是绿灯入口这一决定一致，不做修复；
  注释已改为「跑不通是预期结果」，不再承诺具体失败场景。
- `parity:legacy` 的输出多了一行「本模式是历史溯源对照，不是绿灯护栏」提示，`verify` 链不含它，
  因此脚本本身与全链的通过/失败判定未受影响。
- 无 tag 的工作副本（浅克隆、或只拿 tarball）里 `parity:legacy` 与裸跑 `headless_test.js` 会直接报错，
  不再静默读到工作区文件。本轮认为这是可接受的取舍：`verify` 链的两条绿灯护栏不依赖 tag。
