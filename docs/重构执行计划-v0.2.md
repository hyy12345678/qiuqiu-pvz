## 3. 工作项与验收

### W1 校准 parity 护栏（对应方案 R0.2–R0.3）

**交付**

1. `scripts/check-parity.js` 可被测试 `import`（`main()` 只在直接运行时执行）。
2. 新增 `tests/parity-tool.test.mjs`，用反例证明现有比较的能力边界：
   - 语句换序、跨函数搬动、`import` 增删、字符串内部空白变化 → 现有多集合比较**不报错**（已知盲区，不粉饰）。
   - 真正的行内容增删、同一行多写一次 → 必须 FAIL。
   - 注释变化被忽略；`export` 修饰剥离但函数体仍参与比较。
3. 修正脚本头部与输出中的「行为等价」措辞：它证明的是**规范化行的内容增删**，不是执行顺序、作用域、依赖或行为等价；`import`/re-export 行被过滤，因此 import 变化由 W2 兜住。

**验收**：`npm test` 中 parity 自测全绿；手动往 `src/` 塞一行临时内容仍能触发 FAIL；自测明确列出上述盲区。

### W2 严格源码指纹（对应方案 R0.4–R0.5）

**交付**

1. `scripts/check-fingerprint.js`：遍历 `src/**`（含 `src/shell.html`），按「sha256 + 相对路径」记录**原始 UTF-8 内容**；不排序代码、不删 import、不改字符串。
2. 基线 `scripts/source-fingerprint.txt`，按路径排序，一行一个文件。
3. 命令分离：`npm run fingerprint` 只验证；`npm run fingerprint:update` 才重写基线。`verify` 不自动更新。
4. 失败时列出「新增 / 缺失 / 内容变化」三类路径，不打印源码内容。

**验收**：改一个字节、增删一个文件、改文件名都会 FAIL；未改动时 PASS；`--update` 之后才恢复 PASS。测试证明哈希对单字节变化敏感。

### W3 加固 headless Canvas 桩（对应方案 R0.7）

**交付**

1. `headless_test.js` 的 Canvas 桩改为白名单：实际使用的绘图方法、属性写入、渐变 `addColorStop` 明确支持；未知 API 访问或未知属性写入立即抛错，不再静默返回空函数。
2. 离屏 Canvas（背景缓存）同样受白名单约束。
3. 帧链检查：每次 `requestAnimationFrame` 回调后必须重新排下一帧；中断时报告中断位置并失败。
4. A–I 场景断言一条不减。

**验收**：`npm run test:smoke` 全绿；临时把某个 `ctx` 调用改成不存在的方法会立刻失败；临时删掉 `frame()` 末尾的 `requestAnimationFrame` 会失败。

### W4 真实发布页浏览器冒烟（对应方案 R0.6 第一条路径）

**交付**：`tests/browser/release-smoke.test.mjs`

- 用 `file://` 加载**未经任何测试改写**的 `dist/植物大战僵尸-网页版.html`。
- 不暴露 `G`、不替换 Canvas、不注入调试后门。
- 桌面上下文：真实鼠标从菜单 → 选卡 → 答题 → 开局；键盘 `1`/`P`/`M`/`Esc`。
- 触屏上下文（`hasTouch`）：用 tap 走同一路径，验证触屏入口仍可用。
- 断言：首帧有实际像素、运行中画面持续变化、页面零 `pageerror`、零外部网络请求。
- 测试前要求 `dist/` 已由当前源码构建（`parity:dist` 负责新鲜度）。

**验收**：命令可在仓库内复跑；任一断言失败有明确场景名。浏览器不可用时明确报错退出，不静默跳过。

### W5 受控绘制轨迹基线（对应方案 R0.6 第二条路径）

**交付**：`tests/browser/render-baseline.test.mjs` + `tests/browser/baselines/*.trace.txt`

- 固定条件：种子化 `Math.random`、手动推进的 `performance.now`/`rAF`、固定 `localStorage`、视口 1024×640、DPR 1、Chromium 版本记录、音频替身（无 `AudioContext`）。
- 记录 Canvas 方法调用、数值参数、样式属性写入、渐变创建与 `addColorStop` 顺序；渐变用稳定编号，不用对象地址。
- 场景：菜单、第 3 关选卡、答题页、白天第 1 关开局、夜间第 4 关开局。
- 验证与更新分离：默认只比较；`npm run test:browser:update` 才写基线。差异输出首行差异与上下文摘要。

**验收**：连续两次运行结果一致；临时改一处颜色或坐标会 FAIL 并指出差异；两条浏览器路径的报告分开，不把轨迹基线称为真实音频验收。

## 4. 本轮各类检查分别证明什么

| 检查 | 证明 | 不证明 |
|---|---|---|
| `parity`（行多集合快照） | 规范化行内容的增删 | 顺序、作用域、依赖、字符串内空白、行为等价 |
| `fingerprint`（严格内容哈希） | 是否存在未登记的文件内容变化 | 已登记变化是否正确 |
| `test`（37 条 `node:test`） | 特定规则与边界、护栏工具自身的能力边界 | 画面回归、完整交付流程 |
| `test:smoke`（A–I） | 模块源码上的交互与机制场景 | 真实发布页、真实浏览器合成 |
| `test:browser` 发布冒烟 | 实际交付 HTML 可启动、交互、持续运行、零外部请求 | 全关卡全部玩法正确 |
| `test:browser` 绘制轨迹 | 固定条件下绘制调用与参数一致 | 字体栅格化、真实音频、触屏真机手感 |
| `parity:dist` | 产物对应当前源码构建 | HTML 壳与运行行为正确 |

因此本轮不放行 R1 的依据不是「全绿」，而是上述各项各自被证明到了它该证明的范围。

`headless_test.js` 的 Canvas 桩从 Proxy 自动造函数改为**白名单**：`CTX_METHODS` / `CTX_PROPS` 明确列出实际用到的 API，未知方法访问与未知属性写入立即抛错；离屏上下文同样受约束。两处自检保证「检查本身不会坏掉」：

### 6.7 W6 命令边界

新增 `fingerprint`、`fingerprint:update`、`test:browser`、`test:browser:update`；`verify` 顺序为 `parity → fingerprint → test → build → parity:dist → test:smoke → test:browser`。`build` 与 `verify` 不自动更新任何基线，`test:browser:update` 是唯一写轨迹的入口，`parity:rebase` / `fingerprint:update` 仍是显式人工动作。

`tests/browser/artifacts/` 已加入 `.gitignore`（失败现场，不入库）；`tests/browser/baselines/` 则必须入库。

### 6.8 已知缺口（带进 R1）

1. **轨迹不覆盖音频**：轨迹路径把 `AudioContext` 置空，声音相关逻辑只保证不抛错，不保证音色/时序；真实音频仍依赖人工试听。
2. **轨迹对浏览器版本敏感**：字体栅格化与 Chromium 绘制细节变化会让轨迹失效。升级 Playwright/Chromium 时必须 `npm run test:browser:update` 并在此记录新版本号。
3. **发布冒烟只走第 1 关开局**：全部关卡、全部植物、报纸僵尸等仍由 A–I 与手工清单覆盖，浏览器层不重复。
4. **`npm test` 不包含浏览器测试**：glob 是 `tests/*.test.mjs`，`tests/browser/` 由 `test:browser` 单独跑；两者都在 `verify` 里，但单独跑 `npm test` 时看不到浏览器结果。
5. **「全新检出」未实测**：本轮验证发生在一个已安装 `node_modules` 与 Playwright/Chromium 的工作区；`npm ci` + `npx playwright install chromium` 之后能否一条命令复跑，属于未验证项。
