# 球球的植物大战僵尸 · 工程化重构方案 v0.1

> 目标：开发态拆成模块化工程，发布态仍是**一个可直接双击打开、零外部资源的离线 HTML**。
> 约束：重构期间游戏行为与画面无回归；每一阶段结束时都能交付一个可玩产物。

---

## 1. 目标与非目标

### 目标
- 把 3157 行单文件拆成有边界的模块，逻辑（simulation）与画面（render）可独立测试。
- 引入构建工具与开发服务器/ watch，改代码不必手工重排大文件。
- 测试从「一个正则抠脚本的冒烟驱动」升级为「单元测试 + 发布产物回归」。
- 发布产物保持现有全部特性：程序化绘制、Web Audio 合成、离线、触屏、`localStorage` 存档。

### 非目标（本轮不做）
- 不引入前端框架（React/Vue）、不做 CSS/静态资源管线。当前没有任何外部图片与音频文件，全部代码生成，资源管线是纯负担。
- 不做新玩法内容（新植物/新关卡）。内容改动留到重构完成后的独立轮次。
- 不改美术与数值。任何「顺手调一下」的诱惑都应在重构中被拒绝。

## 2. 现状量化（决定成本的几个数字）

| 项 | 计数 | 含义 |
|---|---|---|
| `ctx.` 引用 | 1119 处 | 所有绘制函数闭包引用顶层 `let ctx`；这是拆模块最大的摩擦点 |

## 3. 待你拍板的四个决策（我给了推荐值）

| # | 选项 | 推荐 | 理由 |
|---|---|---|---|
| D1 | 打包器：**esbuild** vs Vite | **esbuild** | 无框架、无 CSS 管线、无 TS（本轮），Vite 的价值主要恰在这三者。esbuild 单文件 bundle + `--watch` 已够快；产物体积可控，接入手写 inline 脚本最直白 |
| D2 | **是否上 TypeScript** | **本轮不上**，先做 P0–P6；TS 作为重构后的独立小轮次 | 一次性同时改「结构 + 类型」会把可验证的纯代码搬迁变成难以 diff 的重写；类型收益在模块边界清晰后才显现 |
| D3 | 状态传递：**显式传 `world`** vs 保留模块单例 | **simulation 层显式传参，render 层允许共享 target** | 见 §5 |
| D4 | 测试框架：**node:test**（内置，零依赖） | **node:test** | 保持「clone 后 `npm i` 只装一个 esbuild」的极简依赖面 |

以下方案按推荐值编写；若你在 D1/D2 上选了别的，受影响的是 P1（构建脚本换成 Vite 配置 + `vite-plugin-singlefile`）与全程（TS 加 `.ts` 后缀与 tsconfig），阶段划分与顺序不变。

## 5. 核心技术选择：`ctx` 怎么办

1119 处 `ctx.` 引用决定了成本曲线。两条路：

**方案 A｜每个 draw 函数显式接收 `g` 参数**
最干净，但要改 28 个函数签名 + 全部 1119 处引用 + 所有调用点。等价于把 1500 行绘制代码重写一遍，无法用 diff 审查，回归风险最高。

**方案 B｜ES Module live binding（推荐）**
`render/target.js`：

```js
export let ctx = null;
export function setTarget(c) { ctx = c; }        // 仅 boot 与 background.js 允许调用
export function withTarget(c, fn) { const s = ctx; ctx = c; try { return fn(); } finally { ctx = s; } }
```

其余模块 `import { ctx } from './target.js'` —— ESM 的 live binding 语义保证顶层 `ctx` 重绑后，所有引用点自动看到新值，**1119 处一行不改**。原来的 `ensureBG` 换绑手法改写成 `withTarget(bgc, () => paintBattleBG(night))`，语义等价且有 `finally` 兜底（现状若 `paintBattleBG` 抛错会永久留在坏 target 上，这里顺手修掉）。

代价：`ctx` 成了模块级可变共享状态，不是纯函数。约束办法：`setTarget` 只允许在 `main.js`（启动时设 DPR 后的主画布）和 `render/background.js`（离屏缓存）调用，其余模块 lint/评审层面禁止；测试里用 `golden-render` 兜住画面。

**这条方案依赖一个前提，必须在 P1 就单独验证**：esbuild 打包后保留 ESM 的 live binding 语义（被 `import` 的 `export let` 在源模块内重绑后，引用方看到新值）。esbuild 在这点上是正确的，但 P1 结束前用两行代码跑一次确认（A 模块 `export let x`，B 模块 import 后调用 A 的 `setX()` 再打印）。若语义不成立，P4 就必须走方案 A（全量传参），成本从「搬文件」变成「重写绘制层」，整个方案的工期要重估。

D3 的「simulation 显式传 world」与此同理但方向不同：`sim.js`/`entities.js`/`waves.js` 一律 `f(world, ...)`，不 import 全局 `G`；只有 render 层可以共享 target。

### P3 · simulation 核心：`G` → `world`（1–1.5 天）
**做什么**
- `core/world.js` 提供 `createWorld(persist)` / `resetWorld(world, levelIndex, startSun)`，取代 [顶层 G](file:///Volumes/sd/work/4fun/qiuqiu-pvz/%E6%A4%8D%E7%89%A9%E5%A4%A7%E6%88%98%E5%83%B5%E5%B0%B8-%E7%BD%91%E9%A1%B5%E7%89%88.html#L211) 与 [beginPlay](file:///Volumes/sd/work/4fun/qiuqiu-pvz/%E6%A4%8D%E7%89%A9%E5%A4%A7%E6%88%98%E5%83%B5%E5%B0%B8-%E7%BD%91%E9%A1%B5%E7%89%88.html#L237)。
- `core/entities.js` + `core/particles.js` + `core/sim.js`：把 `placePlant`/`spawnZombie`/`damageZombie`/`explode*`/`triggerMower`/`updatePlay` 改为 `f(world, dt)` 形态，**内部不 import 全局**。
- 把渲染专用字段与逻辑字段分开：`AT`（全局动画时钟）与 `hoverCell`/`mouse`/`hotspots` 从 simulation 视野中移走，`sim.js` 不再读写它们（现状 `updatePlay` 只读 `t`，`AT` 只在渲染里用，搬迁时逐处确认）。
- 输入驱动的状态变更（种植、收阳光、选中卡片）抽成显式动作函数 `actions.js`（`plantFromSlot`、`collectSun`、`toggleShovel`…），由 `ui/input.js` 调用 —— 这样测试可以直接调动作而不必模拟点击坐标。
- `world.rng` 注入：粒子、抖动、导弹概率全部走 `world.rng`，为 P6 的确定性重放铺路。

**行为不变量（必须逐条验证，这是本轮最容易出错的地方）**
1. 伤害优先级：护盾（`acc`）先吃伤害，溢出回灌 `hp`（[damageZombie](file:///Volumes/sd/work/4fun/qiuqiu-pvz/%E6%A4%8D%E7%89%A9%E5%A4%A7%E6%88%98%E5%83%B5%E5%B0%B8-%E7%BD%91%E9%A1%B5%E7%89%88.html#L445)）。
2. 报纸僵尸狂暴触发条件：`acc<=0 && !angry && state!=='dying'`，狂暴后 `speed = 34 * rand(0.94,1.08)` 且 `slowT` 清零。
3. 土豆雷不被啃食（`findEatTarget` 跳过）但会被撑杆僵尸视为可跳目标（`!(potato && !armed)`）。
4. 火炬转火豌豆：`prevX < p.cx && pea.x >= p.cx` 的跨格判定，`dmg *= 2`，火豌豆溅射 20 伤害/45px 同行。
5. 导弹 3×3 判定用 `Math.floor((x - LX)/CW)`，与本体命中判定坐标系一致。
6. 小推车只在 `state==='idle'` 触发的行生效，`z.x < LX+14` 触发、`z.x < LX-72` 判负。
7. 夜间关卡不掉天降阳光 + 开局 `+100` 补偿 + `nightHint` 8 秒。
8. 胜利条件：`evIdx >= events.length && zombies.length === 0 && t > 0` 后累计 1 秒。

**完成定义**：`sim.js` 单测不再需要 canvas/DOM 桩（只 stub `persist` 与 `audio`）；上述 8 条各有一条命名测试；`npm run build` 后可玩；parity 脚本 PASS。
**回滚**：`world.js` 前 P2 状态是独立提交，revert 即可。

### P4 · render 层拆分（1.5–2 天，最重的一步）
**做什么**
- 先落 `render/target.js`（§5 方案 B），`main.js` 启动时 `setTarget(cv.getContext('2d'))` 并完成 DPR scale。
- 按 §4 的文件切分把 28 个 `draw*` 函数物理搬迁，**函数体一个字符不改**（含魔法数字与配色）。搬迁用剪切而非重写。
- `render/background.js`：`ensureBG` → 以 `withTarget` 实现，缓存 key 从 `(bgCanvas,bgTheme)` 收进模块局部变量；昼/夜两套主题的乘色、星空、月晕、窗光、雾气全部原样保留。
- 迁移顺序（每迁一个文件就 build 一次并肉眼比对，不要一次性全搬）：
  `paint.js` → `projectile.js`+`mower.js`（小）→ `plant.js`（640 行，最大）→ `zombie.js`（360 行）→ `hud.js` → `scene/*`。
- 绘制里的状态读取（`G.sun`、`G.slots`、`G.hoverCell`、`AT`）改为显式参数 `drawXxx(world, t)`；`AT` 由 `game.js` 传入，不再靠顶层变量。

**风险与对策**
- **风险 1｜不可见的绘制顺序/坐标系差异**。对策：P6 的 golden-render 轨迹测试先于本阶段最后两步建立——搬完 `paint.js` 就立刻给菜单界面打一份轨迹快照，后续每搬完一类就重放比对。
- **风险 2｜`rr()` 依赖当前路径状态、`O()` 依赖 `ctx.beginPath` 前后关系**。这类隐式协议必须在搬迁时保持紧邻顺序，禁止顺手「优化」成 helper。
- **风险 3｜`ctx.save/restore` 不配对**。在 `target.js` 加一个仅开发态开启的计数断言（`save`/`restore` 进出差值归零），跑一遍全关卡截图点；确认无泄漏后关闭。

**完成定义**：`src/main.js` 仅剩装配代码；四个界面（menu/help/select/play）与两套背景的轨迹快照全部与基线一致；`npm run build` 产物人工试玩 4 关通过。
**回滚**：本阶段内部再切 6 个子提交，按文件回退。

### P5 · 场景 / HUD / 输入 / 状态机收口（0.5–1 天）
**做什么**

## 7. 阶段依赖与时间线

```
P0 ─→ P1 ─→ P2 ─→ P3 ─→ P4 ─→ P5 ─→ P6
基线   管线   叶子   逻辑   画面   输入   测试/发布
                └──── golden 快照在 P4 中途开始建立 ────┘
```

串行，不可并行：P3 与 P4 都会触碰同一批函数签名，并行只会制造冲突。
总量程约 **5–7 个专注工作日**（含 4 关手工试玩回归），其中 P4 占三分之一。

## 8. 每阶段的统一验收仪式

每阶段结束必须跑完这四步，任一失败就不进下一阶段：

1. `node scripts/check-parity.js` —— 规范化 diff 仍为 PASS（P4 之后放宽为「仅代码移动」白名单）。
2. `npm test`（P2 起）/ `node headless_test.js`（P2 前）。
3. `npm run build` + 双击 `dist/` 产物，**手工试玩第 1 关全程 + 第 4 关前 60 秒**（覆盖昼夜两套背景）。
4. `git diff --stat` 自查：本阶段变更文件是否都在计划清单内，有无「顺手改数值」。

## 9. 已识别风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 1500 行绘制代码搬迁出现肉眼难辨的偏移 | 美术回归 | golden 轨迹测试（P4 中途建立，越早越好）；禁止「边搬边优化」 |
| `ctx` 共享可变 target 掩盖 save/restore 不配对 | 偶发画面错乱、难以定位 | 开发态计数断言 + 全关卡路径点检 |
| hotspot 后注册优先的隐含契约被「整理」成正序 | 结算面板按钮失效 | 一条专项回归测试锁死 |
| 注入 `rng` 改变出怪/粒子随机性表现 | 手感漂移 | `rng` 默认实现为 `Math.random`，不改分布；parity 白名单标注签名变更 |
| 中文文件名在构建脚本里的编码问题 | 发布产物写错位置/乱码 | 文件名写成 `scripts/build.js` 顶部常量，并在构建后断言产物存在且非空 |
| 重构周期内新玩法需求插入 | 两套改动互相污染 | 内容需求一律排到 P6 之后；确需插入则开分支 |
| 一次性大提交无法审查 | 出错无法定位 | 每阶段至少一个提交，P4 按文件切 6 个子提交 |
