# 球球的植物大战僵尸 · 深度重构与优化方案 v0.2

> 日期：2026-10-28
> 状态：供评审的实施建议；文档交付不代表已经批准或完成代码重构。
> 基准：当前工作区源码，包含尚未提交的蘑菇、咖啡豆、全部关卡开关及测试改动，不仅是 `HEAD`。
> 核心目标：从“代码搬进多个文件”深化为“边界清楚、战斗可复现、改动可验证”，发布仍为一个双击可玩的完全离线 HTML。

## 1. 结论与实施原则

项目有继续深化重构的必要，但不需要推倒重写或引入游戏引擎。

当前已经具备 esbuild 构建管线、核心模块和一组有价值的行为测试；剩余问题主要是共享可变状态、输入与规则混杂、随机源互相干扰，以及测试对打包后内部名称的依赖。继续只按行数拆文件，无法解决这些问题。

推荐顺序：

```text
R0 护栏校准与发布页基线
  → R1 显式 world 与实例隔离
  → R2 随机源分流与外部副作用隔离
  → R3 动作入口与界面状态分离
  → R4 渲染、输入、循环的物理拆分
  → R5 测试迁移收口与发布验收
```

五条原则：

1. **先建立对应测试，再改对应边界**，不以重新盖章替代验证。
2. **结构迁移与规则变更分开**，不夹带新植物、数值调整或美术修改。
3. **按依赖方向拆分，而不是按文件长度拆分**。
4. **每个阶段都能构建、运行和独立验收**，不留下长期双实现。
5. **优先解决可验证性与可维护性**，性能优化必须先有测量证据。

### 1.1 本轮不做

- 不引入 React/Vue、ECS、通用插件系统、全局事件总线或复杂依赖注入容器。
- 不同时迁移 TypeScript，不重写全部 Canvas 函数为显式 `ctx` 参数。
- 不引入联网资源、外部图片/音频、服务端或在线存档。
- 不把确定性测试扩展成面向玩家的录像、回放或中途存档功能。
- 不改成固定时间步循环，不调整碰撞算法、数值、绘制层级与触屏行为。
- 不因为某段代码“以后可能变大”就提前拆出抽象层。

## 3. 深层问题与优先级

### 3.1 最高优先级：parity 的保证范围被高估

[scripts/check-parity.js:133–141](../scripts/check-parity.js#L133) 对源码去注释、压缩行内空白、过滤导入、剥离导出修饰并排序；[247–248 行](../scripts/check-parity.js#L247) 先拼接所有源码文件，再统一处理；[275 行](../scripts/check-parity.js#L275) 比较的是行多集合。

因此它能发现很多行内容的增删，却不能证明：

- 语句执行顺序没变；
- 代码仍位于原来的函数或作用域；
- 导入关系没变；
- 文件边界没变；
- 字符串内部空白完全没变。

[259–260 行](../scripts/check-parity.js#L259) 声称导入参与比较，与实际实现相反。这是需要修正的工具契约，不是注释措辞的小问题。

`parity:dist` 有独立价值：检查交付脚本是否对应当前源码的构建结果；但它不是运行测试，也不证明当前源码与上一个版本行为一致，更不覆盖整个 HTML 壳。

**决策建议：保留搬迁对照价值，撤回行为等价承诺。** 不为追求绿色结果而不断扩大忽略规则。

### 3.2 高优先级：world 只是换了存放位置

[world.js:11–27](../src/core/world.js#L11) 的单例同时保存实体、资源、关卡流程、鼠标、悬停和热点；[sim.js:7–11](../src/core/sim.js#L7) 直接导入存档、音频和这个单例。

后果是：

- 无法自然地创建两个互不影响的战斗实例；
- 测试需要反复手动清理共享状态；
- UI 与逻辑可任意修改同一个对象，不能从函数签名判断写入范围；
- 将文件继续拆小，并不会自动缩小修改的影响范围。

这里需要的是显式实例与写入口，而不是把 `G` 改名成 `world` 后继续导出单例。

### 3.3 高优先级：表现随机与战斗随机互相干扰

已确认的路径：

- [util.js:4–5](../src/core/util.js#L4)：`rand/randi` 消费全局 `Math.random`；
- [sim.js:67](../src/core/sim.js#L67)：球球导弹概率消费同一随机源；
- [main.js:2381–2382](../src/main.js#L2381)：震屏绘制消费同一随机源；
- [sfx.js:47–59](../src/audio/sfx.js#L47)：音频噪声生成也消费同一随机源。

受控实验使用 seed `12345`、固定 `dt=1/60`、相同世界初始化、相同 24 次强制就绪射击，并保持震屏有效：

| 调度 | 结果 |
|---|---|
| 只更新、不绘制；重复运行 | 射击序列一致，首次导弹在第 14 发 |
| 同样更新，每步额外执行实际 `render()` | 首次导弹变为第 10 发，后续序列也变化 |

这是测试夹具中的因果验证，不是正常一局的性能或胜率数据。

**结论：只给全局 `Math.random` 固定种子不够。** 如果战斗与表现仍共享流，改变绘制次数、粒子数量或音频能力，就可能改变后续战斗抽样。

### 3.4 高优先级：规则与输入、悬停提示多处耦合

[main.js:1660](../src/main.js#L1660) 的选卡逻辑检查冷却与阳光；[2422 行](../src/main.js#L2422) 的按下处理同时负责热点、收阳光、铲除、普通种植和咖啡豆；[1815 行](../src/main.js#L1815) 的悬停预览又维护一份目标判断。

这不是已经证明所有路径都有 bug，而是新增特殊卡片时容易遗漏规则的结构原因。

应将“能否对这个格子使用这张卡、成功后扣多少钱、进入什么冷却”收成动作入口；输入负责定位目标，渲染负责显示同一判断结果，不再分别实现规则。

### 3.5 高优先级：冒烟驱动绑定内部名称，渲染检查偏弱

[headless_test.js:22–37](../headless_test.js#L22) 将源码打成 ESM 后作为普通脚本放入 VM，拒绝真正的 IIFE 产物；[75–85 行](../headless_test.js#L75) 通过共享作用域操作内部变量。

这会让合法的模块封装或打包器同名消歧变成测试失败，而不是游戏失败。

[Canvas Proxy:44–54](../headless_test.js#L44) 对未知方法返回空函数，大部分渲染场景仅验证“不抛错”；配色赋值正确，也不代表画出了正确的形状、顺序和位置。

需要区分三个问题：逻辑是否正确、画面是否回归、交付 HTML 是否真正可运行，不能指望一个 VM 驱动同时替代三者。

## 4. 不可破坏的约束

### 4.1 发布与运行约束

- 发布文件仍为 [dist/植物大战僵尸-网页版.html](../dist/植物大战僵尸-网页版.html)，无运行时依赖，`file://` 双击可玩。
- Canvas 程序化美术、Web Audio 合成、触屏与本地进度保留。
- 逻辑分辨率保持 1024×640，DPR 上限与现有坐标换算策略不变。
- 保留 `dt = Math.min(dt, 0.05)`、现有暂停语义与更新顺序，不借机更换时间模型。
- 保留真实解锁进度与“全部关卡”开关的独立存储语义，不互相覆盖。
- 不把测试导出、调试命令或源码模块请求带进真实发布文件。

### 4.2 行为约束

以测试与代码共同界定，不单凭注释：

- 护盾先承伤、溢出扣本体；报纸狂暴与减速清除保持现状。
- 土豆雷啃食/撑杆目标规则、跨火炬判定、导弹范围保持现状。
- 小推车触发、死亡清理、失败与胜利结算时机保持现状。
- 昼夜开局阳光、夜间无天降阳光、蘑菇睡醒规则保持现状。
- 阳光飞到资源栏后到账的时机保持现状，不能改成点击立即到账。
- 咖啡豆无效目标不消耗、不冷却、不取消选卡；成功后才提交动作结果。
- 热点“后注册先命中”、收阳光与种植的输入优先级保持现状。
- 不把测试名称当作完整规格：发现实现与预期不一致时单列缺陷，由用户决定是否修复，不混入机械迁移。

## 5. 目标架构：足够清楚，不做通用引擎

### 5.1 依赖方向

```text
main.js：创建实例、注入浏览器适配器、启动
  └─ game.js：调度动作、推进世界、刷新界面、执行帧循环
       ├─ core/：世界与规则，可脱离浏览器测试
       ├─ render/：读取世界和界面状态，输出 Canvas 与热点描述
       └─ ui/：坐标与设备事件 → 动作

core/ 不 import main、game、render、ui、audio 或浏览器存档实现
render/ 不调用种植、伤害、存档等变更函数
ui/ 不直接扣阳光、推进冷却或修改实体集合
```

允许渲染读取纯数据表、常量与只读规则查询；禁止通过这些查询暗中修改世界。

### 5.2 状态归属

| 对象 | 负责内容 | 边界 |
|---|---|---|
| `world` | 流程状态、暂停、关卡、题目、进度、资源、卡槽冷却、实体、事件与战斗时钟 | 每次工厂调用创建独立容器；不保留鼠标、热点或 DOM 引用 |
| `world.visual` | 粒子、焦痕、震屏、闪光、波次文字、夜战提示、呻吟计时等表现数据 | 保持现有更新阶段与暂停时机；不能反向影响战斗判定 |
| `ui` | 鼠标、悬停、当前选卡、铲子与热点注册表 | 每个游戏实例独立；不能作为种植合法性的权威来源 |
| `renderState` | 动画时钟、背景缓存、Canvas target、绘制随机源 | 不使用战斗随机源，不修改战斗字段 |
| 浏览器适配器 | 音频播放、本地进度读写、事件监听、帧请求 | 由装配层创建并注入；核心测试使用记录型替身 |

将表现数据暂时归入 `world.visual`，是为了保留原本更新时机并避免过度拆分，不是宣称世界已经成为完全纯粹的领域对象。

实体上的动画初相、后坐力等字段可暂留原位置并标明为表现数据；`deathT`、阳光飞行进度等虽然看似动画字段，却影响清理或资源到账，必须保留在战斗比较中。

### 5.3 最小接口约定

以下是目标接口，不是已经存在的 API；参数最终命名可以调整，但职责不能重新混合。

| 接口 | 责任 |
|---|---|
| `createWorld({ progress, rng, fxRng })` | 创建独立世界；只使用传入的初始进度，不自行读取存储 |
| `beginPlay(world, startSun, ports)` | 按已有流程初始化一局；不共享数组、不遗留旧局引用 |
| `step(world, dt, ports)` | 保持现有阶段顺序推进世界；不导入浏览器对象 |
| `placePlant(world, type, row, col, ports)` | 内部实体操作，调用者为已通过校验的动作或测试夹具 |
| `checkUseCard(world, slotIndex, row, col)` | 只读判断冷却、资源、占格和特殊目标，返回统一的有效/无效结果 |
| `useCard(world, slotIndex, row, col, ports)` | 再次执行权威校验，成功后一次性应用效果、扣费、冷却 |
| `render(world, ui, renderState)` | 绘制并生成供输入使用的热点描述，不改战斗状态 |

`ports` 只提供实际需要的同步边界，例如 `sound(name)`、`saveProgress(value)` 与 `saveUnlockAll(on)`；不用字符串查找任意服务，不引入事件总线。

默认浏览器适配器保持现有声音与存档时机，测试适配器记录调用以便断言；无存储权限等浏览器边界行为沿用现有语义，不扩展为新的恢复系统。

`world` 可以被函数原地修改；本轮目标是确定性和可隔离性，不要求不可变数据结构或每帧复制整个世界。

### 5.4 随机源划分

| 随机流 | 用途 | 禁止用途 |
|---|---|---|
| `world.rng` | 出怪行、速度扰动、射击概率、资源生产时刻、战斗相关抽样 | 粒子、音频、绘制抖动 |
| `world.fxRng` | 粒子、实体动画初相、表现计时等 | 战斗与资源判定 |
| `renderState.rng` | 震屏等纯绘制抽样 | 推进或改变世界 |
| 音频模块局部随机源 | 噪声与音色扰动 | 影响任何其他随机流 |

运行时在装配阶段生成种子，再用现有种子 PRNG 创建独立流；测试显式给定种子。派生规则固定，不依赖“先创建哪个模块”或“先调用几次随机”。

仅仅把多个参数都赋值为 `Math.random`，仍然是同一个随机源，不能通过隔离验收。

题目与波次已有的 `rng` 参数继续保留；不用为统一风格给不需要整个世界的纯函数强行传 `world`。

### 5.5 建议目录

路径代表职责归属，不要求第一轮创建全部文件；保留现有模块，按阶段移动。

```text

  core/

    particles.js             表现数据生成，使用 fxRng
    constants.js util.js rng.js quiz.js waves.js
    data/                    已有数值表
  audio/sfx.js               浏览器音频实现
  platform/persist.js        从当前 core/persist.js 迁出
  render/
    target.js                共享 Canvas target 的唯一写入口
    paint.js background.js
```

## 6. 分阶段实施与验收

### R0：校准护栏，建立可相信的起点

**目标：在新增大规模结构改动前，知道每个检查究竟证明什么。**

工作项：

1. 将当前已存在的功能改动与新重构改动分开核对；经用户确认后形成可恢复基点，不自动提交、清理或覆盖工作区。
2. 为 parity 自身补测试：导入替换、语句换序、跨函数搬动和字符串空白变化，明确现有多集合比较会漏掉哪些情况。
3. 修正工具输出与文档的行为等价承诺；原行多集合仅作为搬迁辅助检查保留。
4. 新增严格源码指纹清单：以文件路径和原始 UTF-8 内容哈希记录源码及 HTML 壳，不排序代码、不删除 import、不修改字符串；清单只能在审查差异和测试之后更新。
5. 精确指纹用于发现未登记变更，不用于证明变更正确；有意搬文件也会触发检查，这是接受的代价。
6. 补真实发布 HTML 的浏览器冒烟，以及受控条件下的关键界面绘制基线。
7. 加固 Canvas 桩：未知 API 应失败；覆盖实际调用的方法与属性；预期应继续运行的帧链中断时明确失败。

**两条浏览器路径必须分开：**

- 发布冒烟：加载未经测试改写的实际 HTML，通过鼠标/触屏/键盘与 Canvas 交互，检查首帧、持续运行、进入战斗、页面错误和外部请求；不暴露 `G`，不替换真实 Canvas。
- 受控画面基线：独立浏览器上下文固定时间、rAF 推进、初始存储、随机源、浏览器版本、字体、视口和 DPR；必要时使用音频替身，但不能把这一路说成真实音频验收。

单例尚未拆除时，优先通过真实输入到达菜单、选卡、答题与开局；难以稳定到达的深层战斗夹具，待 R1 暴露模块接口后补齐，不向发布 IIFE 插入调试后门。

**工具建议：** 保留 `node:test`，浏览器驱动可选 Playwright 作为纯开发依赖；是否引入依赖需在实施前确认。本次只写方案，不安装。若不引入可在项目内复跑的驱动，则浏览器自动化项仍未完成，不能以一次人工操作或专有工具会话冒充仓库级自动测试。

**完成标准：**

- 24 条现有测试与 A–I 场景不减弱；新增护栏测试能验证自己的失效检测能力。
- 原样发布页启动、进入战斗且持续运行，零未捕获应用错误、零外部请求。
- 菜单、选卡、答题、昼夜开局的受控视觉基线可重复。
- 同一工作区无意修改 import 或交换有依赖的语句，严格指纹会失败。
- 快照更新与构建命令分开，验证命令不得自动重盖章。

### R1：显式 world 与实例隔离

**目标：让核心函数的作用对象清晰可见。**

建议拆成两个小步：

1. 先将实体、粒子与模拟调用改为显式接收对象；暂用现有 `G` 作为调用参数，不同时改变数据结构或随机抽样顺序。
2. 再引入世界工厂，由装配层创建实例；移除核心对模块级 `G` 的导入，并迁移对应单测为直接 import 调用。

同步为声音/存档预留显式 `ports` 参数；此阶段默认适配器仍保持原有调用时机，尚不宣称已完成全部副作用隔离。

**必须补的测试：**

- 创建 A、B 两个世界，数组、格子、卡槽和题目状态不共享。
- 在 A 种植、伤害、重开关卡，不改变 B。
- A、B 交错推进，不发生对象串写。
- 重置后不保留旧局实体引用，真实进度与全部关卡开关语义不变。

**完成标准：** 核心操作均能显式选择世界，原不变量与对应直接 import 测试通过。

**边界：** 本阶段证明的是内存实例隔离；在 R2 完成之前，不宣称两个实例的随机轨迹和外部副作用已经完全独立。

### R2：随机分流与副作用隔离

**目标：是否绘制、生成多少粒子、音频是否可用，不再改变战斗结果。**

工作项：

1. 分类所有直接及间接随机调用，包括 `rand/randi`、实体初始化、音频噪声和呻吟计时，不能只替换 `sim.js` 的 `Math.random`。
2. 按 §5.4 引入独立流，规则函数显式使用战斗流，表现函数使用表现流。
3. 将 SFX 调用改为同步端口调用；将浏览器存档实现迁出核心，由装配层注入初始进度和写入回调。
4. 将粒子、震屏等收进 `world.visual`，保留现有一帧中的更新位置。
5. 不顺便换碰撞、时间步、随机分布、概率阈值或实体排序。

**这是有意的轨迹变化，不是纯搬迁。** 随机流拆分后不要求仍在第 14 发或第 10 发生成导弹；保留的是概率规则和玩法约束，新增的是表现独立性。需要单独审查并批准新轨迹基线。

**验收矩阵：** 同一战斗 seed、初始状态、动作序列和 `dt` 序列下，对比以下执行方式：

- 每步不绘制、绘制一次、额外绘制多次；
- 粒子正常生成与禁用表现生成；
- 音频可用、不可用，以及不同音频随机流；
- 单独运行 A，与 A/B 两世界交错运行。

上述方式的战斗状态投影必须一致；表现状态可以不同。

战斗投影保留实体数组顺序、生命/护甲、位置、状态、影响未来逻辑的计时、弹丸、阳光到账进度、卡槽冷却、事件游标、资源与胜负等；排除纯配色、震屏与无关粒子。不能直接把整个含函数/引用的对象 `JSON.stringify` 后当作证明。

另用可控抽样值检查 15% 概率边界，并用固定多 seed 检查分布与关卡节奏没有明显偏移；有限样本不是严格概率证明，也不替代人工手感回归。

### R3：动作入口与 UI 状态分离

**目标：点击只是输入方式，不是规则的唯一载体。**

工作项：

1. 将 `mouse/hoverCell/sel/shovel/hotspots` 从世界移入 `ui`。
2. 增加有限的显式动作：使用卡片、铲除、收阳光、选择关卡、回答题目、暂停等，不建设可扩展命令框架。
3. 普通种植与咖啡豆共用卡片使用入口，在分支内处理不同目标规则。
4. 冷却、资源和目标判断由只读查询与提交动作共享；提交时再次校验，失败不得部分扣费或改变目标。
5. 动作返回成功/失败及必要原因，界面据此保持或清除选择；不要把 UI 对象传入实体函数。
6. 热点从“携带修改世界的闭包”改为“携带动作描述”，由调度层执行；注册顺序仍决定覆盖优先级。

**必须补的测试：**

| 情形 | 必须保持的结果 |
|---|---|
| 阳光不足、冷却未结束、普通植物点占用格 | 不种植、不扣费、不进入新冷却 |
| 咖啡豆点空格、清醒植物或非法目标 | 不扣费、不冷却、不取消选择 |
| 咖啡豆点睡眠蘑菇且资源足够 | 唤醒、扣费、冷却、取消选择各发生一次 |
| 铲除与收阳光 | 目标选择、资源到账时机和输入优先级保持原状 |
| 暂停或非战斗状态 | 禁止不适用的战斗动作，界面导航仍按现有行为工作 |
| 同一逻辑格子由鼠标与触屏选择 | 得到相同的动作结果 |

**完成标准：** 核心动作可直接测试；渲染与输入不再直接扣费、推进冷却或修改实体集合。

### R4：拆分渲染、输入与循环

**目标：主入口只负责装配，不再承载业务和美术细节。**

子步骤按依赖顺序推进：

1. `render/target`：用 ESM live binding 保留原绘制代码的 `ctx` 访问方式；用同步 `withTarget` 和 `try/finally` 恢复离屏 target。
2. `paint/background`：迁出基础画法和背景缓存，保持渐变、路径和缓存行为。
3. `projectile/mower`：先搬规模较小的绘制对象。
4. `plant/zombie`：原样搬迁美术函数，不借机改坐标、描边、配色与分支。
5. `hud/scenes`：显式读取 `world/ui/renderState`，生成热点描述。
6. `ui/input + game`：迁移事件绑定、流程调度和帧循环，完成主入口收口。

每个子步骤先搬迁函数体，再单独审查参数或 target 调整；引入 import 会触发严格源码检查，必须作为明确的迁移差异登记，不能扩充忽略规则绕过。

**渲染边界：**

- `ctx` 允许是受约束的共享 target，但只允许装配和离屏绘制切换它。
- `withTarget` 不跨异步操作，不用于多实例并发绘制；不同实例按顺序绑定目标绘制即可。
- 背景绘制失败时恢复 target，缓存只在绘制成功后标记有效；作为独立小改动测试。
- `AT` 由调度层推进并传入，不重新藏进另一个全局单例。
- `save/restore`、路径命令、样式赋值和渐变 stop 顺序都进入轨迹检查。
- 日夜切换、DPR 1/2、暂停、结算遮罩、睡醒植物等各有验收点。

**输入边界：**

- 1024×640 逻辑坐标、缩放映射、`passive:false` 与 `preventDefault` 组合保持现状。
- 后注册热点先命中，遮罩按钮不能被下方卡片抢走。
- 键盘 1–8、Esc、P、M 与鼠标/触屏保持原行为。
- 不把 Canvas 热点重构成一套新的 DOM UI。

**完成标准：** 绘制轨迹与基线一致，真实浏览器可玩，主入口只装配，设备输入回归通过；不以“main.js 少于某行数”替代验收。

### R5：测试迁移与发布收口

工作项：

1. 汇总 R1–R4 已迁移的直接 import 测试，将剩余 A–I 场景迁移到稳定接口；等价覆盖完成前不删除旧断言。
2. 删除测试对打包后内部变量名、全局 `ctx` 和 `bgTheme` 的依赖；真实发布测试仍通过用户输入执行。
3. 验证 pretty/minified 两种交付方式，分别执行构建一致性、离线检查和浏览器冒烟，最终保留选定的标准产物。
4. 校对构建戳、文档入口和开发命令；`dev` 会写入 dist，验收前必须重新生成标准发布构建。
5. 只有在有可恢复基点并得到用户明确确认后，才清理根目录旧 HTML、legacy 或旧工具；不把历史溯源件默认当作可删除垃圾。
6. 混用 CJS 工具与 ESM 源码的 Node 警告单独处理；不能直接给根包添加 `type: module` 而不迁移 `require` 脚本。当前 `>=20` 的版本声明也应验证真实支持范围，不能仅凭本机通过就声称整个范围可用。

**完成标准：** 发布页实际运行测试进入可复跑流程，源码测试不依赖打包器局部命名，文档与交付入口不再歧义，单文件离线承诺保持。

## 7. 测试体系与“重新盖章”规则

### 7.1 各类检查分别证明什么

| 检查 | 负责证明 | 不负责证明 |
|---|---|---|
| 原行多集合 parity | 规范化后的行内容是否增删 | 顺序、作用域、依赖与行为等价 |
| 严格源码指纹 | 是否存在未登记文件内容变化 | 已登记变化是否正确 |
| 单元/不变量测试 | 特定规则与边界成立 | 全部画面和完整交付流程 |
| 固定输入状态轨迹 | 固定条件下关键战斗演化一致 | 所有随机种子和所有平台 |
| 绘制调用轨迹 | 方法、坐标、样式、渐变与调用顺序一致 | 字体栅格化、浏览器合成与真实音频 |
| 浏览器截图 | 固定环境的最终画面无明显偏移 | 所有设备都逐像素一致 |
| 发布 HTML 冒烟 | 真正交付文件可启动、交互与持续运行 | 全关卡全部玩法正确 |
| `parity:dist` | 交付脚本对应指定参数下的源码构建 | HTML 壳与运行行为正确 |
| 静态离线扫描 + 运行时请求监控 | 已扫描模式及已执行路径没有外部依赖 | 对全部未来路径的形式化证明 |

### 7.2 轨迹记录要求

- 记录方法调用，也记录 `fillStyle/strokeStyle/font/globalAlpha` 等属性写入和渐变 stop；只记录方法名不够。
- 为渐变、离屏 Canvas 等对象分配稳定的测试身份，不用对象内存地址参与比较。
- 固定初始存储、时间、随机流、浏览器与 DPR；初始化绘制和缓存命中绘制分别建立基线。
- 保留可阅读的差异或摘要；哈希仅用于快速判断，不作为唯一排障信息。
- 数值容差需有理由，不随失败扩大；绘制轨迹不能替代真实浏览器截图与触屏验收。

### 7.3 更新基线的顺序

1. 先确认属于机械迁移、规则修复还是有意随机轨迹变化。
2. 看清源码差异与旧基线的失败原因，不先运行 `parity:rebase`。
3. 新增能够约束该变化的测试；对机械迁移检查旧/新实现的行为对照。
4. 运行已有回归、对应浏览器路径和必要人工验收。
5. 由评审确认后更新指纹或快照，并记录变更类别与理由。

禁止用一个无限增长的逐行豁免表掩盖行为改写，也禁止让 `verify/build/test` 自动覆盖基线。

### 7.4 命令边界

现有 `npm run verify` 包含构建，会更新发布文件；仅审查时可使用 §2.2 的只读检查组合。

建议未来新增独立的浏览器、绘制与严格源码检查命令，但这些命令目前尚不存在，R0/R5 实施后再登记到包脚本；在浏览器依赖不可用时明确报告未完成，不能静默跳过后仍显示全绿。

## 8. 性能优化：先测量，再决定

当前没有证据表明需要对象池、空间索引、OffscreenCanvas 或 Worker。本轮不把这些列为必做项。

### 8.1 建议测量场景

在固定设备与浏览器记录以下场景，重复采样并注明版本：

- 白天常规布阵；
- 夜间一大波僵尸；
- 球球导弹与火豌豆造成大量粒子；
- 选卡页和暂停/结算界面。

记录更新与绘制耗时的 p50/p95、长帧、活动实体/粒子数量、长时间运行后的内存趋势；不只记录平均 FPS。60Hz 的理论帧预算约 16.7ms，不能把它写成所有设备都已达成的承诺。

### 8.2 有证据后再考虑的优化

| 候选 | 当前线索 | 实施前提 | 回归关注 |
|---|---|---|---|
| 减少每帧按行过滤和排序 | [main.js:1843–1846](../src/main.js#L1843) 每行过滤并排序僵尸 | 测量确认这里占用显著 | 绘制层级、同坐标稳定顺序 |
| 限制纯表现粒子数量 | 爆炸与移动可持续生成粒子 | 真机出现粒子相关长帧 | 只影响表现，不影响战斗随机和伤害 |
| 缓存重复静态绘制 | 已有背景缓存 | 确认创建/绘制成本高且可正确失效 | 昼夜、DPR、字体与主题变化 |
| 提取射击参数到植物表 | 射速、伤害、速度散在 sim 分支 | 先完成行为测试，逐项有明确收益 | 不做万能行为 DSL，不调数值 |

不为微小收益把原本清晰的数组扫描改成索引维护系统；小规模塔防中，维护成本可能高于运行收益。

### 8.3 体积检查

审查时 pretty 产物为 154777 字节，约 151.1 KiB。后续与同一功能集、同一构建参数的基点比较，不再与缺少新功能的 legacy 比较。

建议把增长超过 5% 设为需要说明的评审提示，而非未经测量的硬性否决线；minified 体积应在 R0 单独记录，不能混用 pretty 基线。

## 9. 风险、顺序与回退

| 风险 | 控制方式 |
|---|---|
| 当前工作区功能改动与新重构混在一起 | 先确认范围与可恢复基点，不自动提交/暂存/丢弃已有工作 |
| 换 world 参数时遗漏调用方 | 按模块迁移、构建与测试同步，双实例测试发现串写 |
| RNG 分流导致轨迹不同 | 单列有意变化；保持规则和分布，以独立性矩阵验收 |
| 声音和存档迁出后时机变化 | 同步端口、记录型替身，验证次数与调用顺序 |
| 把动画字段当成无关数据删掉 | 按是否影响未来规则分类，尤其死亡清理和阳光到账 |
| 渲染拆分后图像偏移 | 搬迁前建轨迹与截图，逐类移动，不边搬边美化 |
| Canvas target 未恢复或缓存半初始化 | `try/finally` 与成功后提交缓存，异常路径测试 |
| 测试“修到通过”但断言变弱 | A–I 覆盖映射逐项审核，旧断言等价迁移后才删除 |
| 浏览器驱动不可用却声称全绿 | 独立报告自动化/人工验收状态，缺项即不放行对应阶段 |

R0–R4 的接口相关工作顺序推进，不并行改同一批签名；浏览器夹具、静态护栏测试等互不依赖的准备工作可以并行。

每个阶段建议形成独立、已验证的变更单元。需要 Git 提交或回退时先得到用户授权；对已提交单元优先创建反向提交，不使用破坏性重置覆盖未提交工作。

不承诺固定工期：R0 的浏览器基线和 R4 的美术搬迁通常是主要工作量，先完成 R0 再依据实际基线稳定性估算后续。

### 10.1 实施前需要确认的事项

- 是否接受 Playwright 作为仅测试使用的开发依赖；不改变发布物的零依赖属性。
- 是否批准 R2 的随机流隔离及对应新轨迹基线；它不是纯文本搬迁。
- 当前未提交功能改动如何形成可恢复基点；本方案不自动提交。
- 根目录旧 HTML、legacy 与旧工具何时清理；未确认前不删除。

其他事项采用本文的保守默认：继续使用 esbuild、Canvas、Web Audio 与 `node:test`，保持单文件离线交付，不扩大玩法范围。

## 11. 建议的第一轮范围

**先仅实施 R0，不同时大拆 main.js。**

第一轮应交付可准确解释能力边界的检查工具、稳定发布页冒烟、基本绘制基线与可恢复的工作起点；通过这些门槛后，再推进 `G → 显式 world`。

最终成功标准不是“文件变多了”，而是：核心可独立测试、视觉与声音不干扰战斗、输入不再承载重复规则、交付物真正经过执行验证，同时游戏的玩法、画面与离线使用方式保持可控。
